## 2. 关键 API 选型（1.21.1 特有）

| 需求 | 1.21.1 的正确 API | 注意 |
|---|---|---|
| 物品属性数据 | **Data Components**（`DataComponentType`），不是 NBT | 1.20.5+ 已移除物品 NBT，鱼的"长度/重量/稀有度"必须用组件 |
| 玩家持久数据 | **AttachmentType**（NeoForge）或 `PlayerEvent.Clone` 手动拷贝 | 用 Attachment 支持 `copyOnDeath` |
| 全局持久数据（排行榜） | `SavedData`（`DimensionDataStorage`） | 存主世界 |
| 自定义网络包 | `PayloadRegistrar` + `CustomPacketPayload`（`StreamCodec`） | 1.21 用 `StreamCodec` 而非旧的 `FriendlyByteBuf` 直接写 |
| GUI | `AbstractContainerMenu` + `AbstractContainerScreen` | 用 `MenuType` 注册 |
| HUD | `RegisterGuiLayersEvent`（NeoForge） | 1.21 用 GuiLayer 而非旧的 RenderGameOverlayEvent |
| 实体渲染 | `EntityRenderer` + `EntityRenderersEvent.RegisterRenderers` | 浮漂可用简化的自定义渲染器 |
| 数据包 JSON 重载 | `AddReloadListenerEvent` | 支持 `/reload` 热加载鱼种 |
| 配置 | `ModConfigSpec`（NeoForge `ModConfigSpec.Builder`） | 分 COMMON / SERVER / CLIENT 三类 |
| 附魔 | `DeferredRegister<Enchantment>` + `EnchantmentEffectComponents` | 1.21 附魔改为数据驱动，工作量大，可放 M2 后期 |

> ⚠️ **风险提示**：1.21.1 的附魔系统（`EnchantmentEffectComponents`）是数据驱动的，注册自定义附魔比 1.20 复杂得多。建议把"远投/柔韧/识鱼"三个新附魔**排到 M6/M8**，M1–M5 先用配置项模拟效果，避免早期卡在附魔数据上。

## 3. 服务端权威架构

```
客户端                                    服务端
────────────────────────────────────────────────────────────────
玩家长按右键
  └─ 本地表现：蓄力条增长
  └─ 松开 → CastPayload(power, yaw, pitch) ──────►
                                          计算抛物线 → 生成 BobberEntity
                                          ◄────── SessionSyncPayload(落点, 距离, 水深, 水体类型)
  渲染浮漂飞行 + 落水
玩家右键提竿
  └─ HookPayload ─────────────────────────────►
                                          校验窗口 → 进入 FIGHT
                                          （咬钩时已扣耐久）
每 tick 输入
  └─ InputPayload(reel|release|neutral, dir) ──►
                                          TensionModel.tick()  ★服务端算
                                          FishStruggleModel.tick()
                                          ◄────── SessionSyncPayload(张力, 体力, 距离, 方向)
  客户端：仅做渲染与插值（不判定）
上鱼成功
                                          ◄────── CatchPayload(鱼定义, 长度, 重量, 评级, 收益)
  渲染结算卡片
```

**为什么必须服务端权威**：
1. 防止客户端改张力值/改咬钩概率（单人也会被玩家自制外挂破坏乐趣）
2. 多人服务器是未来的必然需求（你已选"多人同步"）
3. 排行榜数据必须可信

**客户端插值**：服务端 20 TPS 下发状态，客户端在两次同步之间做线性插值（`Mth.lerp` + `partialTick`），保证张力条**视觉上顺滑**而不是 20fps 跳动。这是"手感"的关键工程细节。

### 4.2 耐久扣除（你的规则，集中在两个方法里）

```java
/** 咬钩瞬间调用一次，与后续成败无关 */
private void applyBiteDurabilityCost() {
    ItemStack rod = player.getMainHandItem();
    // 鱼竿：按稀有度基础损耗 × 材质系数 × Boss倍率 × 尺寸系数 × 附魔修正
    int rodCost = RodStats.durabilityCost(rod, targetFish, fishLength);
    DamageItem(rod, rodCost);

    // 鱼线：固定 -1
    ItemStack line = TackleBox.getLine(player);
    LineStats.damage(line, 1);
}

/** 断线时额外扣除 */
private void applyLineSnapPenalty() {
    LineStats.damage(TackleBox.getLine(player), 5);   // 额外 -5
    RecipeManager.consumeBait(player, 1.0f);          // 饵 100% 损失
    player.getCooldowns().addCooldown(rod, 160);      // 8s 冷却
}
```

## 5. 水族箱方块实现

| 部分 | 方案 |
|---|---|
| 方块 | `AquariumBlock`（透明玻璃材质，`noOcclusion`），带 `BlockEntity` |
| 多格合并 | 相邻水族箱方块通过 `BlockEntity` 邻居查找形成一个"水箱组"，共享鱼列表；从任意一格打开是同一个 GUI |
| 鱼渲染 | 不用真实体（性能），在 `BlockEntityRenderer` 里用**带动画的 2D 精灵**沿预设路径游动；每个水箱最多渲染 6 条 |
| 鱼的成长 | `BlockEntity` 每 6000 tick（5 分钟）tick 一次：`weight += 生长速率`（上限为该鱼最大值），并检查喂食状态 |
| 水质 | 三个状态：清洁 / 一般 / 浑浊（影响成长速度与观赏值）；用海带/水桶清理 |
| 观赏值 | 水箱组总观赏值 = Σ(鱼的稀有度分 × 尺寸评级分)；给半径 8 格内玩家 +1~+3 幸运等级（可配置关闭） |
| 保存 | 鱼列表存 BlockEntity 的 `saveAdditional`/`loadAdditional`，用 `CompoundTag` 的 ListTag |
| 性能 | 只在玩家 16 格内渲染鱼；距离外只 tick 成长逻辑（低频） |

> **【开放项7】**：鱼的成长速度默认"5 分钟 ≈ 1% 体重"，从平均值长到最大值约需 8 小时挂机。要不要更快/更慢？

## 6. 网络包清单（Client → Server / Server → Client）

| 包 | 方向 | 频率 | 内容 |
|---|---|---|---|
| `CastPayload` | C→S | 每次抛竿 | `float power, float yaw, float pitch` |
| `HookPayload` | C→S | 每次提竿 | 无（仅触发） |
| `InputPayload` | C→S | 每 tick（仅在 FIGHT 状态） | `byte flags`（bit0 收线, bit1 放线, bit2-3 方向） |
| `SessionSyncPayload` | S→C | 每 2 tick | `byte state, float tension, float stamina, float distance, byte dir, boolean sprinting, short redZoneTicks` |
| `BitePayload` | S→C | 咬钩前 + 咬钩时 | `byte phase`（探饵/试探/吞钩）, `float windowSeconds`, `byte rarityHint`（若附魔"识鱼"） |
| `CatchPayload` | S→C | 上鱼时 | 鱼定义 ID, 长度, 重量, 评级, 收益, 图鉴是否刷新 |
| `ChumSyncPayload` | S→C | 打窝时（广播附近玩家） | 位置, 半径, 剩余时间, 窝料类型 |
| `BroadcastPayload` | S→C | 稀有鱼 | 玩家名, 鱼名, 重量, 稀有度 |
| `OpenMenuPayload` | S→C | 打开 GUI | 菜单类型 + 初始数据 |

**流量估算**：对抗期间 `InputPayload`（≈2 字节）+ `SessionSyncPayload`（≈20 字节）每 tick/每 2 tick → 单人约 22 B/tick，10 人同时钓鱼 ≈ 4.4 KB/s。完全可接受。

## 7. 构建与开发环境（需要我帮你配的部分）

### 7.1 JDK 21 问题

你机器上是 **Oracle Java 22**，NeoForge 1.21.1 官方要求 **Java 21**。两个方案：

| 方案 | 操作 | 优点 | 缺点 |
|---|---|---|---|
| **A. 便携式 JDK 21（推荐）** | 下载 Temurin 21 的 Windows x64 **zip**（免安装），解压到 `我的世界mod/.jdk/temurin-21`，在 `gradle.properties` 里写 `org.gradle.java.home=...` | 不动你系统里的 Java 22；可随项目删除；不需要管理员权限 | 需要下载约 190 MB |
| B. 系统安装 JDK 21 | 用 Temurin/MSI 安装器装在 `C:\Program Files\Eclipse Adoptium\` | 更"正规"，以后别的项目也能用 | 需要管理员权限；可能与 Java 22 的 PATH 冲突 |

我倾向 **A**（工作区隔离、零风险）。**【开放项12】你选哪个？**

### 7.2 首次构建成本

```
下载 Gradle Wrapper      ~130 MB
下载 NeoForge + MC 依赖   ~1.2 GB
首次 build 耗时           10–30 分钟（取决于网速）
生成的运行目录            run/（客户端）、run-server/（服务端）
```
需要联网访问 `maven.neoforged.net`、`repo1.maven.org`、`libraries.minecraft.net`。若你的网络访问这些源不稳定，告诉我，我改用国内镜像。

### 7.3 开发工作流

```
开发循环：
  1. 改代码
  2. `./gradlew runClient` → 启动带模组的 Minecraft（热重载部分资源）
  3. 进游戏实测手感 → 反馈给我 → 调 balance.json
  4. 满意后 `./gradlew build` → 产出 `build/libs/anglertackle-1.0.1.jar`
```

**调试辅助**（我会内置，方便你反馈手感问题）：

- `/anglertackle coins <数量>` 加鱼币

- F3 调试屏增加一行"当前水体类型 / 水深 / 鱼池大小"
