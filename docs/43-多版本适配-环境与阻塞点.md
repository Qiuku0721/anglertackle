## 2. 本机网络：只有 Java 能出网

| 工具 | 结果 |
|---|---|
| `curl`（MSYS） | ❌ `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)` |
| PowerShell 5.1 `Invoke-WebRequest` | ❌ `The SSL connection could not be established` |
| **Java（JDK 21）** | ✅ **全部 200**（forgecdn / maven central / libraries.minecraft.net / piston-meta 全通） |
| maven.neoforged.net（官方源） | ❌ SocketTimeout —— 与仓库注释里写的完全一致，**必须靠 ForgeCDN 镜像** |

**判据**：Gradle 用的是 **Java 的 TLS 栈**，不是 schannel ⇒ **拉新版本依赖这条路是通的**。
已实测下载成功：Minecraft 1.21.8 的 client.jar / server.jar / client mappings、NeoForge 21.4.161 与 21.8.57 的全部产物。

⚠ 推论：任何"用 PowerShell 下载"的做法在本机都行不通，必须走 Java/Gradle。

## 3. 🔴 阻塞点：新版本的 NeoForm 重编译

### 症状

给 1.21.4 或 1.21.8 跑 `createMinecraftArtifacts`，在 **recompile** 这一步失败：

```
*** Started working on recompile
Compiling 5745 source files          ← 1.21.8 那次是 6106，见下
 ERROR Line: 1, ..net.minecraft.world.ticks.package-info...: null in /net/minecraft/world/ticks/package-info.java
net.neoforged.neoform.runtime.graph.NodeExecutionException: Node action for recompile failed
Caused by: java.io.IOException: Compilation failed
```

产物是一个 **22 字节的空 zip**（只有 EOCD）。

### 这个报错是误导的（已证伪）

- 手工解出源码归档（6702 个 `.java`，其中 362 个 `package-info.java`），
  检查 `net/minecraft/world/ticks/package-info.java`：280 字节，注解与 import 都正常。
- 手工用 javac 编这棵树时，**一条 package-info 报错都没有**（其余报错是我类路径没给全）。
- 报错里的 `null` 来自 NFRT 的诊断监听器直接调 `Diagnostic.getMessage(Locale)`
  （反编译 `RecompileSourcesActionWithJDK$1` 确认），该调用在"缺实例"的诊断上会返回 null。

⇒ **不要照着 `package-info` 去查**，那条线索是假的。

### 一次重要的误判（记下来，别重犯）

我一度从字节码里认定"ModDevGradle 的 `getJavaVersion()` 分支写反了，把 1.21.1~1.21.10
全判成 Java 25"。**这个结论是错的** —— 实测报错明确写着：

```
Cannot find a Java installation ... matching: {languageVersion=21, ...}
```

⇒ MDG 要的是 **Java 21**，与我的推断相反。
**教训：反编译看出"像 bug"的分支，必须用一次真实运行去反证，不能直接当结论写下来。**
（本例我按自己写的"报 bug 前要先反证"那条自律住了，才没把这个错结论发出去。）

### 目前真正确定的事实

| 事实 | 证据 |
|---|---|
| 1.21.1 **能**编 | NFRT 缓存记录里 target java version=21、`--release 21`，输入是 `transformSources`（5745 个文件） |
| 1.21.8 **能**编（换 ECJ） | `Wrote 9341 class files (51884056 bytes)`，`BUILD SUCCESSFUL` |
| 1.21.4 **不能**编（javac 与 ECJ 都不行） | javac：同一个误导性 package-info 报错；ECJ：`TrialSpawnerConfig` 的 NPE |
| 与 MDG 版本无关 | 2.0.131 / 2.0.147 报错完全相同 |
| 与 JDK 25 无关 | 让 Gradle 整体跑在 JDK 25 上，报错不变 |
| 与工具链发现无关 | 显式 `toolsJavaExecutable` / `toolchain` 都试过，报错不变 |

**还有一个没解释清的差异**：1.21.4 那次只编 **5745** 个文件（纯原版源码），
而 1.21.8 那次编 **6106** 个（= 5745 + 361 个 NeoForge 源码）。
5745 这棵树里引用了 `net.minecraft.FieldsAreNonnullByDefault` 却没人提供它 ——
**很可能就是失败的直接原因**（注解找不到 ⇒ javac 报在 `package-info` 上、message 为 null）。
⇒ 明天第一件事应当是**查清"为什么 1.21.4 的输入少了 NeoForge 那 361 个文件"**。

## 5. ✅ 绕法（2026-10-16 已跑通）—— "坏类文件"修复法

### 5.1 一句话

NFRT 用 javac 编不了 1.21.4/1.21.8 的 Minecraft 源码；换 ECJ 能编过，
但 ECJ 产出的 **10908 个类里有 11 个带畸形属性**，javac 拒绝读取，症状是

```
bad class file: neoforge-21.8.57.jar(/net/minecraft/core/BlockPos.class)
  class file is invalid for class net.minecraft.core.BlockPos
```

**⇒ 把这 11 个类用 javac 单独重编、替换回 jar。** 脚本：`build/fix-mc-classes.sh`

实测：重编 **0 error**，产出 42 个 class，11 个全部替换成功；
再编 mod 时"类文件无效"那批错误**全部消失**，只剩真正的 API 变更。

### 5.2 这 11 个类

```
net/minecraft/ChatFormatting          net/minecraft/core/BlockPos
net/minecraft/core/Direction          net/minecraft/server/level/ServerLevel
net/minecraft/util/RandomSource       net/minecraft/world/InteractionHand
net/minecraft/world/InteractionResult net/minecraft/world/entity/player/Player
net/minecraft/world/item/ItemStack    net/minecraft/world/level/Level
net/minecraft/world/phys/BlockHitResult
```

### 5.3 ⚠⚠ 这条路上踩的坑（**每个都让报错指错方向，全记下来**）

| # | 症状（看起来像什么） | 真凶 | 修法 |
|---|---|---|---|
| 1 | `ERROR Line: 1, ..package-info...: null`（像 MC 源码坏了） | NFRT 诊断监听器调 `getMessage()` 返回 null，文件名被截断 | 别照 package-info 查；换 ECJ 绕开 |
| 2 | `bad class file: BlockPos.class`（像 jar 下载坏了） | ECJ 产出的类带畸形 `RuntimeInvisibleParameterAnnotations` | 用 javac 重编这 11 个 |
| 3 | `package net.minecraft.core does not exist`（像 MC 没装） | **我的脚本**把 `-cp` 写成 `-cp -cp`，整个类路径被当成源文件 | 断言 argfile 里 `-cp` 恰好 1 次 |
| 4 | `invalid flag: .../xxx.jar`（像路径非法/命令行太长） | **仓库路径含中文**，javac 按 GBK 解码 UTF-8 的 argfile | jar 全拷到纯 ASCII 目录 `/tmp/atl-cp/` |
| 5 | `file not found: \tmp\atl-src\...`（像文件不存在） | MSYS 的 `/tmp/...` 不是 Windows 路径 | 一律 `cygpath -w` |
| 6 | `package javax.annotation does not exist`（像依赖没下） | 编译期注解不在 MC 的 libraries 里 | 单独补 jsr305 / jetbrains annotations |
| 7 | `cannot find symbol: class Wolf / ForcedChunksSavedData`（像 API 变了） | 类路径混进**旧版** NeoForge（21.1.252 / 21.4.161） | 按版本过滤 `21\.[0-7]\.` |
| 8 | 同上 | 拿**错版本**的源码归档（1.21.4 的源码修 1.21.8 的 jar） | 从归档记录读出内嵌的 `neoforge-<版本>-sources.jar` 再比对 |
| 9 | `IExtensibleEnum not found` | FML 的 loader 是 **9.0.18**，被 `21.x` 过滤误杀 | FML 单独收 |
| 10 | `package net.neoforged.fml does not exist`（像 FML 没装） | 目录名是 `net.neoforged.fancymodloader`（**带点的一整个目录**） | 路径别拼错 |

**共同教训**：这条链上每一环的报错都指向别处。
**判断"是谁坏了"之前，先自证"我的脚手架是好的"** ——
今天有 4 次（#3 #5 #7 #8）坏的是**我的脚本**，不是被修的对象。
