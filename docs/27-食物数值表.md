# 27 · 食物数值表（**实际生效值**）

> 📌 **开工必读** —— 本文件是《垂纶》策划族的一员。动手前先读 `docs/CONVENTIONS.md`（协作规则 + 每轮自我暗示）与 `docs/接力.md`（接手须知）；项目记忆只认 `docs/` 下的文件。

> 这份表回答一个问题：**游戏里吃下去到底回多少**。
> 数字不是照源码抄的 —— `debug/RecipeAudit.java` 会在专用服务器里把每个食物物品的
> `FOOD` 组件**原样读出来**、并把每条菜配方**六个档位各真做一次**，日志即本表来源：
>
> ```
> ATL_AUDIT=true gradlew runServer
> ```
>
> ⚠ 单位（用户专门提醒过）：**1 格 = 一个完整的鸡腿图标 = 2 点 `nutrition`**，
> **半格 = 1 点**。玩家看到的是图标，这里列的是**点数**。
> 另：**饱和度**是隐藏的"耐久"，最终值 = `nutrition × saturationModifier × 2`；
> 本模组用 `modifier = 0.5`，所以饱和度与饱食度**同值**。
>
> `tools/check-food-values.js` 会从 `fishing/FoodValues.java` 复算整张表并逐行比对：
> 改了数值不改这里就会红。

|---|---|---|
| 0 白 | 3（1.5 格） | 3.0 |
| 1 绿 | 4（2 格） | 4.0 |
| 2 蓝 | 5（2.5 格） | 5.0 |
| 3 紫 | 6（3 格） | 6.0 |
| 4 金 | 7（3.5 格） | 7.0 |
| 5 红 | 8（4 格） | 8.0 |

熏鱼 / 炭烤鱼的数值与上表**同一套**吗？不 —— 它们是"菜"，用下面那张表。

## 2. 菜（工作台 10 道 + 熏鱼 + 炭烤鱼）

| 鱼的档位 | 饥饿值（点 / 格） | 饱和度 |
|---|---|---|
| 0 白 | 4（2 格） | 4.0 |
| 1 绿 | 5（2.5 格） | 5.0 |
| 2 蓝 | 6（3 格） | 6.0 |
| 3 紫 | 7（3.5 格） | 7.0 |
| 4 金 | 8（4 格） | 8.0 |
| 5 红 | 9（4.5 格） | 9.0 |

"工作台 10 道" = 红烧 / 清蒸 / 香煎 / 油炸块 / 鱼汤 / 奶白汤 / 慢炖 / 鱼丸 / 刺身 / 整条油炸。
档位取**做菜那块材料的档位**（整条油炸取整鱼自己的档位）。
**同一道菜，鱼越好回得越多**；**同一条鱼，档位越高回得越多** —— 这两条都是用户 2026-10-03 的要求。

## 4. 不能吃的

## 5. 菜型效果：**框架已实现**，11 项效果的**行为也已实现**（1.1.17）

策划见 `docs/28-菜型效果策划.md`（用户 2026-10-03 定案，11 项效果）。

**框架**（1.1.16）：11 项效果**已注册**（`effect/ModEffects.java`，含自己画的 11 张图标）、
**吃菜会给**（`effect/DishEffects.java` + `DishItem#finishUsingItem`），
等级 = 鱼的档位（按各效果"至高"封顶）、时长按材料档位（8:00 起，每级 +2:00），
HUD 上能看到图标与倒计时；同名菜的高低级取舍**走原版的 `MobEffectInstance#update`**。

**行为**（1.1.17，`effect/DishEffectHooks.java`）：渔运（金红总爆率 +3 个百分点/级）、
爆口/空军（>5 kg / ≤5 kg 的鱼种权重 +5%/级，互斥）、巨物猎手（金档以上咬钩回拉 +20%/级）、
强力（远程伤害 +15%/级）、风暴行者（雨天伤害 +20%、移速 +25%/级）、干旱耐受（雨天加成常驻）、
如鱼得水（自然回血 +25%/级）、海洋亲和（水下移速 +25%/级，走 `SWIM_SPEED`）、
两栖（陆地补深海探索者 + 潮涌能量）、
明目（服务端报最近矿物的坐标，客户端按鱼线那套画一条由准心指向它的指引线）。
数值口径与接入点见 docs/28 §7，守着它们的是 `tools/check-dish-effect-hooks.js`。

> 两件事分开写是有原因的：光有"框架"时吃菜能拿到效果、能看到倒计时，但**效果本身没有作用**。
> 分开写才知道该去哪一栏找问题（发不出效果 = 框架，发出了没作用 = 行为）。
