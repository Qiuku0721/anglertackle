## 已经做好的存储层（不用再动）

| 文件 | 作用 |
|---|---|
| `player/PlayerFishingData.java` | 玩家附件：鱼币 + `Map<String, CodexEntry>` + 已领里程碑位掩码 |
| `player/CodexEntry.java` | 单条鱼记录：次数 / 最大最小体重体长 / **最高档位** / 评级位掩码 / 首末时间 |
| `player/PlayerData.java` | 读写附件的唯一入口（`get` / `set` / `update`）|
| `registry/ModAttachments.java` | 附件注册（`serialize` + `copyOnDeath`，每档一份）|

**上鱼记账已接**（`FishingManager.onCatch`）。首次点亮会打日志：
`[垂纶] 图鉴点亮：bluefin_tuna（第 7 种）`。

⚠ `CodexEntry.bestTier` 必须用 `FishData.effectiveTier()` 写入，**不能从 SizeGrade 反推**
—— 金(4) 和红(5) 都落在 RECORD，反推会把金鱼记成红鱼。

## 待实现（按依赖顺序）

### ① 书：`item/CodexBookItem.java`
- 右键 → `PacketDistributor.sendToServer(new CodexRequestPayload())`
- 参照 `guide/GuideBookItem.java`（那边已经是"右键请求 → 服务端下发 → 客户端开界面"）
- 注册进 `ModItems` + 创造页签
- 配方：书 + 任意鱼（或 3 张纸 + 1 条鱼）
- 可选：首次进游戏自动给一本（开放项 15 用户倾向"给"）

### ② 两个网络包（照 `GuidePayload` / `GuideRequestPayload` 的写法）
- `network/CodexRequestPayload`（C→S，无参数）
- `network/CodexPayload`（S→C，**扁平 UTF 字符串**，不传对象图）
  - 每行：`鱼种id|已点亮|次数|最大kg|最大cm|最高档|评级位掩码`
  - 服务端从附件现读；客户端只显示

### ③ 界面：`client/screen/CodexScreen.java`
- 参照 `GuideScreen`：`extends Screen`、固定面板居中、`isPauseScreen()=false`
- **文字一律走 `TextWidget`**（本环境 `drawString` 是糊的）、底色只用 `g.fill`
- 布局：标题栏（`鱼类图鉴　完成度 34%　▓▓▓▓░░░░`）+ 网格 / 列表 + 详情面板
- 未捕获的鱼显示 `?`（**不隐藏**，让玩家知道有什么在等着）
- 详情字段：次数、最大/最小体重体长、最高品质、5 档评级勾选（`seenGrade`）、首次捕获时间

### ④ 完成度奖励：`economy/CodexRewards.java`
- **口径（我定的，可改）**：完成度 = 已点亮鱼种数 / 21；**每点亮 2 种给 50 鱼币**
  （采 `docs/03` §9.1 的现成数字；文档另有两套冲突口径，见 `docs/08` §3.2 开放项 6）
- **必须幂等**：用 `PlayerFishingData.claimedMilestones` 位掩码去重
  （文档完全没写去重机制，这是实现时必须自己补的）
- 发放走 `PlayerData.update` + `ModNetwork.syncCoins`（否则 HUD 余额不刷新）

### ⑤ 自检：`tools/check-codex.js`
- 记账只在 `onCatch` 一处（不能有第二个写入点）
- 奖励幂等（同一里程碑不会重复发）
- 包注册齐全、界面注册齐全
- 语言键齐全（中英）
- 附件不会被写成 `Level` / `SavedData`（那会让"每档一份"失效）

## 用户口径备忘

- **不做物品化的只有鱼币**；图鉴书**是物品**（用户明确要"新书"）
- 图鉴独立于鱼获：鱼卖掉/送人/吃掉都不影响已解锁数据
- 换存档就是另一份图鉴（附件跟着玩家 NBT 走，而玩家 NBT 在各存档的 playerdata 下）
