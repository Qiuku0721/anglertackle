## 0. 一句话

给玩家一个**自己的**设置页 —— 第一项就是"我钓到大鱼要不要全服公告"，
以后新增的玩家级开关**只加一行**，不再往指令里塞。

---

## 1. 现状（为什么现在需要它）

| 事实 | 后果 |
|---|---|
| 模组现在**没有任何"按玩家"的设置** | 所有开关都是**服务器级**配置（`anglertackle-common.toml` / 调参器）⇒ 想关掉"大鱼公告"只能关全服的 ✗ |
| 现有的 6 个界面（图鉴 / 手册 / 商店 / 菜谱 / 改装 / 排行榜）都是"看数据" | 没有一处能"改自己的东西" |
| 玩家数据（鱼币 / 图鉴 / 等级 / 限购）**已经是按玩家持久化**的（附件 + `copyOnDeath`） | ⇒ 加开关**不需要**新造存储体系 ✓ |

> ⚠ 这一条是用户点名要的："**必须在设置界面能自由开关，且持续生效 —— 退出重进也保留上次选择**"
> ⇒ 设置**不能**是客户端临时开关（那种退出就忘 ✗），必须落在**服务端**的玩家数据里。

---

## 2. 原则（与联机策划案 §0 同一套）

| # | 原则 | 具体做法 |
|---|---|---|
| ① | **服务端权威** | 设置存在**服务端**的玩家数据里；界面只是"显示 + 提交"⇒ 客户端改不了别人的、也伪造不了 ✓ |
| ② | **纯加法 / 可整段删** | 关掉/删掉设置界面，行为与现在**逐字一致**（默认值 = 现在的行为）✓ |
| ③ | **默认值必须是"现在正在发生的事"** | 例：公告开关默认**开**，因为本轮公告就是要让它发生；若某天默认要改成关，那就是一次**行为变更**，得单独说 ✓ |
| ④ | **老存档零迁移** | 字段用 `Codec.optionalFieldOf("键", 默认值)` ⇒ 老档读出来就是默认值 ✓（本仓库已经在 `PlayerFishingData` 里这么干了：`guide_given`）|
| ⑤ | **无权限** | 改自己的设置**不需要 OP**（用户 2026-10-11 定的规矩：只有"明显影响平衡"的才要 OP；改自己的公告开关不影响平衡）✓ |
| ⑥ | **没实现的项不许进界面** | 界面里**只放真的会生效的项** —— 放一个"点了没反应"的开关，比没有这个开关更坏 ✗ |

## 3. 第一批设置项（本轮）

| # | 键（附件字段） | 类型 | 默认 | 作用 | 依据 |
|---|---|---|---|---|---|
| 1 | `bigCatchAnnounce` | 布尔 | **`true`（开）** | 我钓到"价值 ≥ 全服阈值"的鱼时，**全服公告**一条 | 用户 2026-10-11："公告可以搞"；定案 6："必须在设置界面能自由开关 + 持续生效" |

**配套的服务器级配置**（不是玩家设置 —— 它们是"这个服多热闹"的尺度，属于服主）：

| 配置键（`[gameplay]`） | 默认 | 作用 |
|---|---|---|
| `bigCatchAnnounceValue` | **5050** | 价值门槛（鱼币）。低于它的鱼**不公告** |
| `bigCatchAnnounceMinIntervalSec` | `10` | 两条公告之间的**最小间隔**（防"一群人同时上鱼"刷屏） |

> ⚠ 阈值口径：用 `CoinPricing.priceFor(档位, 尺寸系数)` —— 与卖价**同一个函数** ✓
> （公告里写的价值与玩家背包里卖出的钱**必须是一个数**，两处各算一遍就会打架 ✗）。
>
> ⚠ **5050 是用户 2026-10-11 亲口给的数，不是随手取的**：红档基准价 4800、尺寸浮动 ±8%
> ⇒ 红鱼价格区间 **[4416, 5184]**，5050 对应"红档里体型系数 ≥ 0.65"（约红鱼的**上游 17%**）；
> 而金档最高只有 1380 × 1.08 = **1490** ⇒ **金档及以下永远够不到**。
> ⇒ 这条门的语义就是"**一条特别大的红鱼**"。改小它 = 把公告变成"谁都能上电视" ✗。
> （钉住这层含义的是 `check-big-catch-announce.js`：它从 `CoinPricing.BASE_BY_TIER` 现算红/金的价格区间，
> 门槛跑出区间、或低于金档上限，都会立刻红。）

**以后可能加的行**（现在**不**放进界面，先记在这里）：
比赛开始提醒（等比赛做完）、HUD 张力条的显示位置、粒子密度、图鉴"未收集也显示"开关。
—— 每一条都遵循原则 ⑥：**实现之后再进界面**。

## 4. 界面设计

### 4.1 入口（两个，都用现成的路）

| 入口 | 做法 | 为什么 |
|---|---|---|
| **手册 / 图鉴里的一个按钮** | 与"排行榜按钮"同一套（`Button.builder(...)` → 发一个 C→S 请求包）| 用户的标准是"**界面才是交付形态**，指令只当调试口"（定案 3）✓ |
| `/atl settings` | 与界面同一条请求包的调试口 | 玩家报问题时能一条指令打开 ✓ |

> 不加新按键（本仓库没有 `KeyMapping`，开界面一律靠物品右键 / 界面里的按钮）。

### 4.2 布局（一页够用，不做分页）

```
┌─ 垂纶 · 设置 ────────────────────────────────┐
│  大鱼公告              [ 开 ]   ← 每行：标签 + 一个开关
│  （钓到价值 ≥ 5050 的鱼时，公告给全服）          ← 第二行：灰字解释"这条设置干什么"
│                                              │
│                                     [ 完成 ] │
└──────────────────────────────────────────────┘
```

- 尺寸走 `UiLayout`（面板按窗口 clamp、行数现算）—— 与另外 5 个界面同一套，**已有的窗口自适应检查器直接覆盖** ✓
- 交互：点一下立刻切换（**不做"保存"按钮** —— 那是"退出时忘了保存"的来源 ✗）；
  切完即发一个 C→S 动作包，服务端写进玩家附件并回一个 S→C 快照（客户端据此刷新显示）
- 文案：每项**两行**（标题 + 灰字解释），解释里**不许写死数字**（阈值来自配置，写死就会与服务器实际值分叉 ✗ —— 本仓库在手册数字上已经踩过好几次）

### 4.3 网络（两个包，与现有 `RankRequestPayload` / `RankPayload` 同构）

| 方向 | 包 | 内容 | 服务端的义务 |
|---|---|---|---|
| C→S | `SettingsRequestPayload` | 空（"我要看我的设置"） | 现读**自己**的附件 → 发回快照 |
| S→C | `SettingsPayload` | `键=值` 的字符串表（只发**界面要用**的项） | —— |
| C→S | `SettingsActionPayload` | `键 + 新值` | **白名单校验**：键必须是已实现的项、值必须合法 ⇒ 只改**发起者自己**的附件 |

> ⚠ 防改包：客户端的动作包**只能**改"自己 + 白名单键 + 合法值"，
> 服务端**不接受**UUID 参数（"改谁的"由连接决定，不由包决定）—— 与排行榜那条"服务端纯读"同一个思路 ✓。

## 5. 兼容性与回滚

| 场景 | 行为 |
|---|---|
| 老存档（没有这个字段） | `optionalFieldOf(..., true)` ⇒ 读出来是默认值 ✓ **零迁移** |
| 玩家死亡 | 附件已经是 `copyOnDeath()` ⇒ 设置跟着走 ✓（不做的话死一次就被重置，玩家会以为界面坏了 ✗）|
| 专用服务器 / 离线服 | 设置**只**影响"我自己的鱼要不要公告"，与 UUID 可信度无关 ✓ |
| 关掉这个界面 | 只影响"能不能改"，**判定照旧读附件**（默认值 = 现在行为）✓ |
| 删掉设置代码 | 行为与现在逐字一致 ✓（公告仍按默认开 + 服主阈值走）|

## 6. 检查器与负例（交付时必须一起给）

| 断言 | 反例（必须红） |
|---|---|
| 每个界面上的键**都在**服务端的白名单里（界面与判定不能两份表）| 界面加一行但白名单没加 |
| 白名单里的键**都真的被某个判定读**（没有"点了没反应"的开关）| 白名单加一个没人读的键 |
| 动作包**不含** `uuid/player` 参数（只改自己）| 给动作包加一个 `targetUuid` |
| 附件字段用 `optionalFieldOf(键, 默认值)`（老档零迁移）| 改成 `fieldOf`（老档直接读档失败/抛异常）|
| 默认值 == 现在的行为（公告默认开）| 偷偷把默认改成关（= 静默改行为）|
| 界面文案里没有**写死的数字** | 把"≥ 5050"写进 lang 文案 |
| 窗口自适应（沿用 `check-ui-fit.js` 那套四种尺寸）| 面板写死尺寸 |
