## 1. 定位与边界

**成就 = 一次性里程碑**：达成即**永久点亮**，与"任务"（`docs/40`，周期性刷新）互补。

| | 任务（`docs/40`） | **成就（本文件）** |
|---|---|---|
| 周期 | **每天/每周刷新** | **一次性，永久** |
| 目的 | 日常节奏、日活 | **长线目标、收集欲** |
| 数量 | 池 ≥8 / 每期抽 5 | **固定 50** |
| 奖励 | 鱼币 / 饵料（二选一） | **25 币 + 20 经验 × 难度倍率**，部分**授予既有称号** |

⚠ **三条不新造**：
1. **不新造奖励通道** —— 全部走**邮件**（`MailService.deliver`）✓；
2. **不新造经验系统** —— 经验只喂 `AnglerLeveling`（卡级规则见 §2.3）✓；
3. **不新造称号** —— 凡与既有称号同条件的，**只调 `Titles.grant` 授予那个既有称号**，**不新增称号** ✓（见 §9）。

## 2. 奖励规则

### 2.1 基础与倍率

| 难度档 | 倍率 | **鱼币** | **经验** | 用途 |
|---|---|---|---|---|
| 普通 | **×1** | **25** | **20** | 入门、顺手达成 |
| 进阶 | **×1.5** | **38** | **30** | 要花点功夫 |
| 困难 | **×2** | **50** | **40** | 需要长期投入 |
| 传奇 | **×3** | **75** | **60** | 全服级 / 极稀有 |

> 取整：`25 × 1.5 = 37.5 → 38`、`20 × 1.5 = 30`；`×2 / ×3` 为整数。

### 2.2 发放

- 达成**当场**由服务端投递一封《成就达成》邮件（模板 `achievement`，附件 = 鱼币 + 经验），
  玩家点【领取】入账 —— **复用邮件的"已读≠已领"与"邮箱满绝不静默丢"**（`docs/36`）✓；
- **幂等**：`AchievementData.unlocked` 已点亮的 id **不再发第二次** ✓。

### 2.3 ⚠ 经验与"卡级"（用户第 ② 条："经验优先以老设计为准"）

垂纶等级**卡在 10/20/30/40 时经验不积攒**（`FishermanProgress.gainXp` / `atGate`）——
**成就经验照老设计走**：**卡级时照发、被丢弃**，**不做"暂存"**（与"钓到鱼给经验"完全同规则，行为一致、好解释）✓。

## 3. 数据模型（新附件 + 数据驱动定义）

### 3.1 成就定义：模板 + 参数（**不写死**）

```java
// achievement/AchievementDef.java
record AchievementDef(
    String id,          // 'a_first_catch' / 'b_gold' …
    Category category,  // CODEX / QUALITY / RECORD / LEVEL / SKILL /
                        // LEAGUE / COOK / TANK / ENV / SHOP / QUEST
    Goal goal,          // 判定条件（见 §4 各条）
    String[] args,      // 参数（只放 id 与数字）
    Tier tier,          // NORMAL / ADVANCED / HARD / LEGEND
    String grantTitle)  // ← 非空 = 达成时**只调 Titles.grant(这个 id)**，不新造称号
)

enum Tier { NORMAL(1.0), ADVANCED(1.5), HARD(2.0), LEGEND(3.0) }
```

### 3.2 玩家数据：**一个新附件**（零迁移）

```java
// player/AchievementData.java   （玩家附件，copyOnDeath，optionalFieldOf 默认值）
record AchievementData(
    Set<String> unlocked,        // 已点亮的成就 id
    Map<String,Integer> counters // 少量需要的累计计数（如"累计上鱼 50 次"）
) {
    static final AchievementData EMPTY = new AchievementData(Set.of(), Map.of());
}
```

- **老存档零迁移**：读不到就是 `EMPTY` ⇒ 老玩家登录后**只在新达成时**点亮（**不追溯补发**，
  否则老玩家一进服瞬间收几十封邮件）✓ —— 这条写进检查器断言；
- **服务端权威**：客户端**只读**，界面不参与判定 ✓。

### 3.3 判定挂钩（**尽量只加一行**）

| 类别 | 已有的公共点 | 怎么接 |
|---|---|---|
| 上鱼类（图鉴 / 品质 / 纪录 / 技法 / 环境） | `LeaderboardHooks.onCatch` | 加一行 `AchievementService.onCatch(player, c)`（包 try/catch）✓ |
| 等级类 | 升级 / 评定通过处 | 加一行 `AchievementService.onLevelUp(...)` |
| 联赛 / 比赛 | `LeagueService` / `ContestService` 的结算点 | 各加一行 |
| 料理 / 水族箱 / 放生 | 各自的完成事件 | 各加一行 |
| 任务 / 活跃度 | `docs/40` 的完成点 | 加一行 |

> ⚠ **纪律**：每个挂钩点都**包 try/catch**、**失败不影响主玩法**（抄 `LeaderboardHooks` 的成例）✓。

### 9.6 ★ 授予幂等核查：**会不会给两次？**（用户第 ③ 条点名）

把真源码逐处查了（`PlayerTitles` / `Titles` / `TitleScreen` / `AnglerCommands`）：

| 环节 | 事实 | 会给人两次吗 |
|---|---|---|
| `owned` 的类型 | **`Set<String>`**（`PlayerTitles.java:39`）| ❌ 不会 —— 重复 add **不会变两个** |
| 授予入口 | **只有 `Titles.grant`**（`Titles.java:184`），内部 `first = !cur.has(id)` | ❌ 不会 —— **只有"第一次"才报提示 + 记日志**，重复调用**静默** |
| 自动授予 | `Titles.syncAuto`（`Titles.java:236`）**幂等**，可随时重复调用 | ❌ 不会 |
| `×N` 显示 | **只在 `repeatable == true` 时显示**（`TitleScreen.java:560`、`AnglerCommands.java:698`）| ❌ 不会 —— 静态成就类称号（`repeatable=false`）**即使计数变 2 也不显示 ×N** |
| 唯一残留 | 不可重复称号重复 `grant` 会让 `counts` 多一个**无意义 +1**（不影响显示/逻辑）| 观感与功能上**无影响** |

**⇒ 结论：引用既有称号不会"给两次"** —— **集合去重 + 首授才提示 + `×N` 只看 `repeatable`**，三道都挡得住 ✓。

**成就侧接入纪律（三道闸）**：
1. 成就**只调 `Titles.grant(id)`**，**绝不自己写 `owned.add`**（否则绕过首授提示与服务端日志）；
2. 成就侧靠 `AchievementData.unlocked` **保证只调一次**（§3.2 的幂等）；
3. **建议加固**：给 `grant` 补一道"**不可重复称号且已拥有 ⇒ 直接 `return false` 且不 `+1`**"的闸 ⇒ **任何调用方都安全**；
   配 `check-titles.js` 一条断言（同一 id `grant` 两次，断言 `countOf` 仍为 **1**）✓。

**与既有自动授予并存**：该称号若**本来由 `syncAuto` 自动授予**，成就那次 `grant` 会因 `first=false` 而**静默返回** ⇒
**不重复提示、不重复发奖**（成就奖励自己走 `unlocked` 幂等）✓。
