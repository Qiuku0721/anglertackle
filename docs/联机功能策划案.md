## 0. 总原则（这一节优先于后面所有内容）

| 原则 | 说明 |
|---|---|
| ① **不改本体手感** ✗ | 联机相关的一切都是**加法** ✓；单机玩家看到的、摸到的，与现在**逐字一致** ✓ |
| ② **默认关闭** ✓ | 所有联机功能挂在开关后面 ✓（例：`multiplayer.leaderboard = false` ✓）⇒ 出问题改配置即可 ✓，不必回滚 jar ✓ |

| ⑤ **数值用调的，不用锁的** ✗ | 不用任何"硬机制"去凑数值目标 ✓（教训：2026-10-09 那套"轮次硬下限"把玩法卡死了 ✗）|

### 1.2 数据从哪来 ✓（关键：已经全部具备 ✗）

- **上鱼判定已在服务端** ✓（`FishingSession` 全程 `ServerPlayer` ✓）⇒ 结算点就是"上鱼成功那一帧" ✓
- 鱼种 / 重量 / 评级 / 回合数 / 耗时 ⇒ **服务端当场都有** ✓（`/atl` 那些指令已经在打这些数 ✓）
- ⇒ **不需要新增任何客户端上报** ✓✓（这是本策划案最省事的地方 ✓：不做"客户端上报成绩"✗，从根上杜绝改包 ✓）

### 1.3 存哪 ✓

- `SavedData`（**世界级** ✓，跟着存档走 ✓）：`atl_leaderboard`
- 键：`玩家 UUID` ✓；值：各榜的"当前纪录 + 达成时间 + 上下文（鱼种/重量/评级）"✓
- 只在**上鱼时写一次** ✓ + 内存里缓存 ✓ ⇒ 不做每 tick 计算 ✗（性能 ✓）

### 1.4 怎么给人看 ✓

- **第一步：指令** ✓（仓库既有文化："先做指令，界面随后接 ✓"，见 `AnglerCommands` 的注释 ✓）
  - `/atl rank` ⇒ 默认总榜前 10 ✓
  - `/atl rank <维度> [页码]` ⇒ 指定榜 ✓
  - `/atl rank me` ⇒ 自己在各榜的位置 ✓
- **第二步：界面** ✓（图鉴/指南已经有 Screen 骨架 ✓，做一个"排行榜"页 ✓，走同一套 UiLayout ✓）

### 1.5 边界与坑 ✗

| 坑 | 处理 |
|---|---|
| 单人存档 / 局域网 / 专用服务器 **三套数据混在一起** ✗ | 榜**跟着存档走** ✓ ⇒ 天然分开 ✓；不同服务器各是各的 ✓ |
| 离线服务器（`online-mode=false` ✓）**认名字不认人** ✗ | 榜按 UUID 存 ✓，显示名字 ✓；**明说**"离线服的成绩只能算社区信用"✓ |
| 有人开小号刷总榜 ✗ | 总榜按**玩家**计 ✓（不按 IP ✗）；不额外反小号 ✓（不值得 ✗）|
| 旧存档没有这份数据 ✗ | 读不到就**从零开始** ✓（不报错 ✓）|

### 1.6 回滚 ✓

- 纯加法 ✓ + 默认关闭 ✓ ⇒ 关掉配置 = 完全消失 ✓（残留的 `SavedData` 是孤儿数据 ✓ 无害 ✓）

## 2. 其他联机功能（按价值 / 风险排序 ✓）

### 2.1 ★★★ 钓鱼比赛 / 锦标赛（最契合多人 ✓）

- **做什么**：服务端定时开赛（例如 10 分钟 ✓）；期间按"最重一尾"或"总重量"计分 ✓；结束后广播名次 ✓、给称号 ✓
- **为什么**：排行榜是"静态的过去"✓，比赛是"正在发生的事"✓ —— 多人真正的乐趣在这 ✓
- **风险**：低 ✓（全在服务端 ✓，不改任何钓鱼手感 ✓）
- **纯加法**：✓（新指令 `/atl contest start|join|stop` ✓）

### 2.2 ★★★ 钓上来的"展示"给周围人看（社交反馈 ✓）

- 别人上鱼时，附近玩家能看到：鱼名 + 重量 + 评级（聊天栏/悬浮提示 ✓）
- 上大鱼时的小特效（粒子/音效 ✓，**可选开关** ✓）
- **风险**：低 ✓；注意**只发给附近玩家** ✗（不要全服广播 ✓）

### 2.3 ★★ 对抗状态对旁观者可见（补偿"看不见" ✓）

- 就是刚修的那条线的延伸 ✓：张力条 / 遛鱼状态 / 是否力竭，显示给**附近**玩家 ✓
- 目的：别人能看懂"你现在很危险"✓，才有围观感 ✓
- **风险**：中 ✓（要新增同步包 ✓，且必须**距离剔除** ✓ + 频率限制 ✓）

### 2.4 ★★ 窝料（chum）与鱼群的共享规则（必须先定案 ✗）

- 现在这个问题**没定案** ✗：窝料效果是"放的人独享"✓ 还是"这片水域共享"✓？
- 建议：**同一水体共享** ✓（更真实 ✓、更有协作 ✓）⇒ 但必须防"一个人一直打窝全队吃"✗（上限 ✓）
- **风险**：中 ✓（要改的是判定归属 ✓，**属于动本体逻辑** ✗ ⇒ 要用户拍板 ✓）

> ✅ **2026-10-11 落地**（用户定案："同一水体所有人共享 ✓；上限的规则是**全服至多存在 40 个窝料**"）
>
> **① 共享这一半：其实一开始就是共享的 ✓** —— 加成判定从来只看**落点**
> （`ChumManager.findChumAt(level, bobberPos)`：把浮漂扔进白圈就有加成，**不看这条窝子是谁打的**）。
> `ChumEntity` 里那个 `ownerUuid` 只是留给"自己的窝子"提示用的，**没有参与任何判定** ✓。
> ⇒ 这一半的工作是**把它锁死**：`check-chum.js` 现在断言 ChumManager 里不许出现 owner、
> FishingSession 两处调用点附近的实参只许是落点（负例 `chum-owner-gate` 把 owner 过滤加回去，必须红）。
>
> **② 上限这一半：新做**（`fishing/ChumRegistry.java`，世界级 SavedData
> `data/anglertackle_chum.dat`，格式 `窝料 UUID → 到期时刻`）。
> ⚠ **为什么不能"数一数世界里的窝料实体"**：窝料寿命是 `durationMinutes × 1200` tick
> = **30~300 分钟**，而 `getEntities` 只数**已加载区块** ⇒ 玩家走远、区块一卸，
> 几十条窝子就查不到了 ⇒ 上限形同虚设 ✗（而那正是要防的刷法）。
> 所以记的是**名额**：抛出时占一格，到期自动作废，实体被 `/kill`/爆炸提前清掉时立刻还回来。
> - **占名额在 `addFreshEntity` 之前** ⇒ 满员时连物品都不扣、不摆臂、不生成实体
>   （负例 `chum-cap-after-spawn` 把顺序倒过来，必须红）；
> - **只在 `KILLED` / `DISCARDED` 时释放** —— `UNLOADED_TO_CHUNK` / `UNLOADED_WITH_PLAYER` /
>   `CHANGED_DIMENSION` 三种情况下窝子**还存在**（在区块存档里 / 在别的维度），
>   释放了就等于"把窝子扔远处、回来再打 40 个"✗；
> - 名额到期时刻与实体寿命**同源**（`ChumEntity.lifeTicksOf()`，全仓只此一处算式）——
>   两处各写一份必然漂移成"窝子还在、名额已放"或反之；
> - 上限值走调参器：`[chum] serverCap`（默认 **40** ✓，`/atl config reload` 即生效）；
> - 玩家看得见：满员时动作栏提示"已到全服窝料上限（N 个）"，
>   `/atl config list` 会打印"当前占用名额 X/40"。
>
> **③ 老存档**：没有那份 `.dat` ⇒ 读出空表 ⇒ 上限从不触发 ✓（已有窝子不占名额，它们到期后世界就一致了）。

### 2.5 ★ 组队（共享"今日最佳"✓，不共享图鉴 ✗）

- **不建议**共享图鉴/等级 ✗ —— 那会破坏"自己钓到自己收集"的核心 ✓
- 可做：组队后共享"今天队里最好的三尾"✓（纯展示 ✓）

### 2.6 ✗ 玩家间交易（建议**不做**）

- 物品复制/刷金币的经典雷区 ✗；真要做只能做"服务端单向兑换"✓（鱼 → 鱼币 ✓）
- **结论：本轮不做** ✗（写在这里是为了"明确划掉"✓，避免以后反复讨论 ✓）

### 2.7 ★ 统计面板 `/atl stats [玩家]`

- 上鱼数、各档分布、最好的一尾、平均遛鱼回合 ✓ —— 排行榜的"个人版" ✓，实现成本极低 ✓
