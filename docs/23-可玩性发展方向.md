## 1. 方向 A · 时间 / 天气 / 月相（推荐第一个做）

### 1.1 为什么是它

它**不加一条鱼、不加一个贴图**，却让已有的 28 条鱼多出一倍的可钓性；而且它能
接进**所有已有系统**：图鉴显示"何时能钓到"、手册多一章、认证考核可以布置
"在雨夜钓一条鲇鱼"这类任务、每日任务有了天然的随机维度。

### 1.2 时段口径（用原版时间刻度，不引入新的时间概念）

原版一天 = **24000 tick**。划分如下（边界值待你确认）：

| 时段 | 时间区间（tick） | 换算 | 现实时长 |
|---|---|---|---|
| 清晨 Dawn | `23000 – 1000` | 日出前后 | 约 2 分钟 |
| 白天 Day | `1000 – 11000` | | 约 8.3 分钟 |
| 黄昏 Dusk | `11000 – 13000` | 日落前后 | 约 2 分钟 |
| 夜晚 Night | `13000 – 23000` | | 约 8.3 分钟 |

**月相**：`level.getMoonPhase()` 返回 0–7（0 = 满月）。只取满月（0）与新月（4）两端做效果，
中间相位不额外处理——这样玩家能靠"抬头看月亮"自己判断，不需要 UI 告诉他。

### 1.3 数据源：给鱼加"出没条件"

不新建数据文件，**扩 `tools/fish-habits.json`**（已有 7 种习性的那份），每条鱼加两组字段：

```json
"golden_loach": {
  "habits": ["bottom", "shy"],
  "time": ["day", "dusk"],          // 缺省 = 全天（all）
  "weather": ["clear", "rain"],     // 缺省 = 全天气（all）
  "moon": "any"                     // any | full | new
}
```

### 1.4 数值口径：只影响"抽到哪条鱼"，不改咬钩节奏

**这是本节最重要的设计约束。** 咬钩等待时间是你亲手定的手感（基础 2–8s、硬上限 20s、
台钓 −30%、打窝再降），环境系统**不许碰它**，否则你上次调好的节奏会全部作废。

所以环境只作用于**权重**：

```
最终权重 = 基础权重（按 minTier 查表）
         × 习性匹配（已有：拟饵对上习性 ×1.10）
         × 时段系数
         × 天气系数
         × 月相系数
```

| 条 件 | 系数 | 说明 |
|---|---|---|
| 鱼的活跃时段与当前时段相符 | **×1.60** | 这是主力效果 |
| 鱼的活跃时段与当前时段相邻 | **×1.00** | 无惩罚、无加成（避免"白天啥也钓不到"） |
| 鱼的活跃时段与当前时段相反 | **×0.45** | 仍能钓到，只是难 |
| 鱼的活跃时段 = `all` | **×1.00** | 全天鱼不吃时段红利，作为稳定选项 |
| 天气相符（如"雨天活跃"遇上降雨） | **×1.50** | |
| 天气 = `all` | ×1.00 | |
| 天气不符（晴天钓雨天鱼） | **×0.60** | 雷暴算降雨的加强：**×1.80** |
| 满月夜 + `moon: "full"` | **×2.00** | 稀有鱼的"脉冲窗口" |
| 满月夜 + 其他鱼 | ×1.00 | 不惩罚 |
| 新月夜 + `moon: "new"` | **×1.60** | 洞穴鱼专用窗口 |
| 乘积上下限 | **钳在 [0.10, 4.00]** | 防止极端天气把某条鱼抬成必然 |

**时段/天气对咬钩速度的唯一影响**（一处，可关）：

- 台钓在夜间等待 **−10%**（夜钓的实际体验），配置项 `biteNightCutPercent = 10`，默认开。
- 除此之外**一个字都不改**。

## 2. 方向 B · 钓点养成（窝点热度）

### 2.1 目的

现在"抛在哪"完全不重要。做成"老钓位"之后，玩家会自发形成"我的钓点"——
这是**低成本、高归属感**的一类系统：不需要新贴图，只需要一组坐标数据。

### 2.2 数值口径

每个"钓点"以**区块坐标**（chunkX, chunkZ）+ 维度为键，存两个数：

| 字段 | 含义 | 范围 |
|---|---|---|
| `heat` | 热度 | 0 – 100 |
| `lastActive` | 最后活跃的游戏时刻 | gameTime |

**增长**（三种行为，均按次计）：

| 行为 | 热度增量 |
|---|---|
| 在该点打窝（窝料入水） | **+8** |
| 在该点成功上鱼 | **+1**（白绿） / **+2**（蓝紫） / **+4**（金红） |
| 单次会话上限 | 每 5 分钟最多涨 **+15**（防挂机刷） |

**衰减**：每 **1 游戏日**（24000 tick）**−3**，但**不低于 0**。
—— 即"一个月不去的钓位"热度掉光，但不会变成负数、也不需要玩家维护。

**效果**（线性，全部有硬上限）：

| 效果 | 公式 | 满值（100）时 |
|---|---|---|
| 咬钩等待 | `×(1 − heat/100 × 0.25)` | **−25%（即最多省 1/4 等待）** |
| 大鱼权重 | 体型上限 `×(1 + heat/100 × 0.10)` | **+10% 体型** |
| 稀有度权重 | 蓝紫以上权重 `×(1 + heat/100 × 0.15)` | **+15%** |

⏳ 待拍板：满值效果是否就是 **−25% / +10% / +15%**？或者你觉得太强/太弱。

### 2.3 展示

- HUD 或浮漂附近显示一行：**"此处鱼群：冷清 / 一般 / 活跃 / 沸腾"**（4 档，阈值 0/25/60/90）；
- 图鉴记录每条鱼的**钓获地点**（可选：只记水体类型 + 是否高热度点）；
- 手册加一节"养窝"。

### 2.4 落点与风险

| 要改 | 文件 |
|---|---|
| 数据存档 | 新 `fishing/HotspotData.java`（`SavedData`，类似排行榜的做法）+ `registry/ModAttachments` 或服务器级存储 |
| 咬钩 | `fishing/BiteTiming.java`（接一个乘数） |
| 选鱼权重 | `fishing/FishSpecies.roll(...)`（体型与品质权重） |
| 打窝 | `fishing/ChumManager.java`（入水时加热度） |
| 上鱼 | `fishing/FishingSession.java` 结算处（加热度 + 记录） |

**风险与对策**：

1. **存档膨胀** —— 每个被钓过的区块都留一条记录。对策：只保留
   `heat ≥ 5` 或 30 天内有活动的点；上限 4096 条，超出时按 `lastActive` 淘汰最旧的。
2. **与打窝增益叠加会不会过强** —— 打窝本身已减 35–55% 等待，再叠 −25% 可能让等待接近地板。
   对策：两者叠加后仍受 `biteFloorSeconds = 3` 约束，且热度效果改为
   **"打窝时额外加成减半"**（即已有窝时热度只出一半效果）。这点要实测。

### 2.5 验收标准

1. 同一位置连打 5 次窝后，HUD 显示"活跃"，平均等待比新点短 ≥ 15%；
2. 换到 100 格外的位置，状态回到"冷清"；
3. 用命令把游戏时间推 10 天不回访，热度衰减到 0（可用调试命令验证）；
4. 极值压测：连续打窝 20 次，等待不低 3 秒地板、体型不超上限。

### 2.6 规模

约 **5–7 个文件 / 700–1000 行**。**会动咬钩参数**，需要你再实测一轮验收。

## 3. 方向 C · 纪录汇总页 + 全服播报（几乎零平衡风险）

### 3.1 目的

图鉴**已经**在存每条鱼的最大重量和长度、物品 tooltip **也已经**在显示尺寸评级
（见 §0.3），但**没有任何地方把纪录汇总起来给玩家看**，也没有"这条鱼破纪录了"的
即时反馈。补上展示层，玩家立刻有了"刷纪录"的自驱目标，而且不改任何数值。

### 3.2 三块内容

**(1) 个人纪录页**（图鉴里加一个页签）

| 列 | 数据来源 |
|---|---|
| 鱼名 + 图标 | `FishSpecies` |
| 最大重量 / 体长 | `CodexEntry` 的 max 值（已有） |
| 钓获时间 | `CodexEntry.gameTime`（已有） |
| 尺寸评级 | 已有（`FishData.SizeGrade`），直接显示 |
| 钓获地点 / 时段 / 天气 | 方向 A / B 落地后才有 |

**(2) 尺寸评级** —— ✅ **已完成，不要重做**

`FishData.SizeGrade` 五档 + `grade.anglertackle.*` 文案 + `FishItem` tooltip 都已在位。
本节唯一可选的补充是"**结算界面也显示一次**"（现在只有 tooltip 有），
以及按 `docs/02 §5.1` 的 15/55/85/97 口径复核一遍 `SizeGrade.fromTier` 的阈值。

**(3) 全服榜**（服务器向，单人存档也显示"个人最佳"）

| 榜 | 排序 |
|---|---|
| 单尾最重（分鱼种） | 重量 |
| 单尾最长（分鱼种） | 长度 |
| 图鉴完成度 | 已收集 / 总数 |
| 钓鱼等级 | 经验 |

**播报**：仅在"破纪录级"（`SizeGrade.RECORD`）时全服播报
（`{玩家} 在{水体}钓到 {鱼名} {重量}kg（{长度}cm）`），并且**可在配置里关掉**
（服务器服主可能不喜欢刷屏）。实现上用 `player.getServer().getPlayerList().broadcastSystemMessage(...)`
—— 全代码现在只有 `displayClientMessage`（个人提示），服务端广播是**零基础**。

⚠ **前置：要先有服务器级持久存储**（§0.2 缺口 G）。全代码搜 `extends SavedData` 零命中，
所以这一节实际上包含两件事：① 搭一个 `SavedData`（NeoForge 1.21.1 用
`ServerLevel.getDataStorage().computeIfAbsent(...)`）② 在上面做榜。
**这个存储同时也是方向 B（钓点热度）和 5.1（周赛）的地基**，所以值得先做扎实。

### 3.3 规模与验收

约 **5–7 个文件 / 600–900 行**（含 `SavedData` 基建）。

验收：钓到超过个人纪录的鱼时结算界面出现"新纪录"标记；钓到纪录级尺寸时有全服播报；
把配置里的播报关掉后不再播报；**关服再开**，榜单数据仍在（验证 `SavedData` 真的落盘）。

## 4. 方向 D · 鱼的战斗性格分化

### 4.1 现状与不满

`FightProfile` 已有四个时间参数（冲刺持续/冲刺间隔/转向间隔/疲劳时间）与 `Archetype`，
但**实战手感趋同**——拉大鱼和拉小鱼的区别主要是"数值更大"，而不是"打法不同"。

### 4.2 四种性格（用现有参数就能表达三种）

| 性格 | 参数特征 | 玩家该怎么做 | 能否用现有参数表达 |
|---|---|---|---|
| **爆发型** | 冲刺短而频繁、疲劳快 | 稳住别硬拉，等它虚 | ✅ 现有参数够 |
| **耐力型** | 冲刺长、间隔长、疲劳慢 | 长期拉锯，比谁先没耐心 | ✅ |
| **甩头型** | 转向极频繁 | 手跟着抖，别拉满张力 | ✅ |
| **潜底型** | 往深处钻、需要放线让它走 | 先放线再收 | ❌ **需要新增"泳层/深度"概念**（`FishingSession` 目前只有张力与体力两个轴） |

❌ 不做（用户 2026-10-03）：**潜底型做不做**？做的话要多一套"深度"状态（界面上会多一条信息），
工作量比另外三种加起来还大；不做的话性格就三种。

### 4.3 怎么分配而不是硬编码

在鱼的数据里**直接给参数组合**（而不是在 Java 里写死性格名）：

```json
"bluefin_tuna": { "fight": { "sprintTicks": 90, "sprintInterval": 70, "turnInterval": 160, "fatigue": 520 } }
```

再在手册/图鉴里把参数翻译成人话（"这是一条耐力型，别指望它很快力竭"）。

⚠ **这条会直接改变你已经验收过的手感参数**，属于"必须实测两轮"的改动。

### 4.4 规模与验收

约 **3–5 个文件 / 400–700 行**（不含潜底型）。

验收：连续钓三种性格的鱼，你不用看名字就能说出"这条是爆发型/耐力型/甩头型"。

## 5. 更远的方向（先记着，不当第一批）

### 5.1 限时竞技（每周目标）

- **本周目标鱼种**：每周轮换 1 条鱼 + 1 个条件（如"雨天夜里的胡子鲇"），
  在该条件下钓到的最大个体进入周榜；奖励鱼币 + 一个"周赛徽章"（纯展示物品）。
- 需要：周榜存储（`SavedData`）、周切换逻辑（用 `gameTime / 24000 / 7`）、
  一个入口 UI（可以挂在老柯对话里）。
- 设计要点：**周榜奖励不要给属性**，只给展示物与鱼币，避免"错过一周就落后"。

### 5.2 配件养成（专精）

- 每件配件随使用累积熟练度，**每 10 级解锁一次"微调"**，最高 5 级。
- **只改 `±1~3%` 的微观参数**（张力回复、回拉速度、窗口时长），
  **不突破 `docs/08` 定下的倍率硬上限**（张力 ×1.6 / 回复 ×2.2 / 体力削减 ×1.8）。
- 让"我那根用了很久的木竿"有情感价值，也给耐久消耗一个正向出口。

### 5.3 明确**不做**的（免得以后又翻出来讨论）

| 项 | 结论 | 依据 |
|---|---|---|
| 饵料实体化（水里挂一颗） | ❌ 不做 | 你 2026-09-30 定案取消 |
| 季节系统 | ❌ 不做 | 与 A 的时段/月相功能重叠，且 MC 没有季节概念，需要额外造计时 |
| 鱼的属性随机词条（+力量/+耐力） | ❌ 不做 | 你的定案：品质由窝料/饵料决定，不给鱼加随机词条 |
| 鱼竿耐久归零直接碎裂 | ❌ 不做（用户 2026-10-03） | `docs/08` 开放项 #4（建议做成"破损可修"） |

## 8. 发散：超出原策划案的想法（2026-10-02 追加）

> 用户追加要求："不局限于现有策划案，发散思维，让 mod 有可玩性和持续吸引性。"
> 本节**不受 §1–§6 的里程碑约束**，也不要求你现在拍板；它是一份**点子池**，
> 每条都标了落点与成本，你可以只挑其中一两条。

### 8.0 先说思路：从"给奖励"转向"造故事"

现在的循环是 **钓鱼 → 得鱼 → 卖钱 → 换装备 → 钓更大的鱼**。这个循环的经济学没问题，
但它是"数值循环"，玩家在拿到最后一档竿之后就没有理由继续了。真正让人反复回来的
游戏（钓鱼类尤其）靠的是**三种心理**：

| 心理 | 玩家嘴里的说法 | 现在的 mod 有没有 |
|---|---|---|
| **未知** | "下一竿会不会是那个？" | 弱：鱼种池是固定的，老手能背下来 |
| **掌控** | "我知道那边有鱼，所以我去那边" | **几乎没有**：水下完全不可见，选点全凭习惯 |
| **故事** | "那天晚上它跑掉了，我后来又去了一趟" | **没有**：跑掉就是失败，不留任何痕迹 |

本节所有点子都服务于这三件事，而且**优先做不需要新美术的那些**——理由是：
新贴图/新模型是唯一会拖慢迭代速度的东西，而"信息"与"记录"是纯逻辑，可以做得很快。

### 8.1 点子池（按"改变玩法的程度"排序）

| # | 想法 | 为什么吸引人 | 怎么做 | 落点 | 成本 |
|---|---|---|---|---|---|
| **1** | **水下的信息** | 让"看"变成一种能力：抛竿时水面出现水花/涟漪，**水花大小对应水下鱼群规模**；打窝后能看到鱼星、泡泡、鱼影陆续进窝 | 落点半径内按鱼池权重算一个"规模档"（0–3），给 `BobberEntity` 加一类粒子；窝子加一圈逐渐聚集的鱼影粒子 | `entity/BobberEntity`、`fishing/ChumManager`、粒子 | 中 |
| **2** | **跑了的大鱼（未解之谜）** | 断线/脱钩不再是"什么都没有"，而是变成**一条线索**：水域里从此有一条"没钓上来的鱼"，再遇到它时有专属台词，比上次更大 | 断线时记一条 `EscapeRecord`（鱼种 / 当前估算重量 / 坐标 / 时间）；该点附近把这条鱼的权重抬 3–5 倍；再钓到 → 提示"又是它"，并可能破个人纪录 | 新 `fishing/EscapeRecord`（挂 `SavedData`）、`FishingSession` 断线分支 | 中 |

| **4** | **鱼情日报 / 图鉴的"每日情报"** | 给玩家一个**每天都回来的理由**（而不是每周）：商店界面显示老柯的一句话——"今早河口有金枪鱼的影子""昨晚有人在下游看到雷龙" | 每天按权重抽 1–2 条"情报"，指向真实生效的鱼/时段/水体；玩家照做真的能提高遇到率 | `shop/`、`entity/FishermanEntity`、`FishingSession` | 小 |
| **5** | **饵料发酵 + 偏口** | "等窝发"的仪式感 + 试配方的乐趣：窝料入水后要 30–60 秒才生效，期间能看到鱼陆续靠近；每个水体有偏好饵/泳层，需要玩家自己试出来 | `ChumEntity` 加"发酵计时"，到期才开始加速咬钩；水体偏口表进 `FishWaters`（同一水体给不同鱼种 ±20% 权重） | `fishing/ChumManager`、`fishing/FishWaters` | 小～中 |
| **6** | **拟饵泳层（路亚深度的第二个轴）** | 让路亚真正"分层"：同一片水，浅滩与深槽的鱼完全不同；玩家要按目标鱼调泳层与收线速度 | 需要在 `FishingSession` 里补一个"深度/泳层"状态（和 §4 的潜底型共用同一套基建） | `fishing/FishingSession`、拟饵配件 | 中～大 |
| **7** | **鱼有"力气"以外的差别（个体气质）** | 同样是 5kg 的草鱼，一条爱钻障碍、一条爱原地打转 —— 每次上鱼都略有不同 | 在 `FightProfile` 基础上叠加一层"个体随机偏移"（±15%），咬钩时定死 | `fishing/FightProfile` | 小 |

| **10** | **生态压力（别钓绝了）** | 给"节制"一个游戏内理由：同一位置短时间内反复钓同一种鱼，该鱼种权重会暂时下滑；放生能恢复，放生台终于有正反馈 | 复用 §2 的钓点热度存储，但**只对"过度捕捞"这一个鱼种降温**，并且放生回补 | `fishing/HotspotData`（§2 的）、`block/ReleasePlatformBlock` | 小 |
| **11** | **鱼的迁徙日历** | 让游戏时间"月"这一层有意义：每月（MC 的 8 个月相周期）有 2–3 种鱼"路过"，错过要等下个月 | 用 `gameTime / 24000` 取"季节月"，把 §1 的鱼条件表按月份轮换 | 复用 §1 的 `Environment` | 小 |
| **12** | **传说鱼（有名字的鱼）** | 把最稀有的 1–2 条鱼做成"有名字的存在"：老柯提到它、图鉴里有它的专属页、钓到时全服播报 + 它只在你满足某个极苛刻条件时出现 | 给特定鱼种加"传说"标记 + 专属图鉴页 + 一次性条件（如满月 + 雷暴 + 夜 + 特定窝） | `FishSpecies` + 图鉴 + 播报 | 中 |
| **13** | **鱼市行情** | 给"什么时候卖"一个决策：某些鱼当日价格波动 ±40%，可以囤或等；商店加一行"今日行情" | 每日按种子生成价格系数，`CoinPricing` 乘一下 | `economy/CoinPricing`、`shop/` | 小 |
| **14** | **老柯的剧情线** | 给 NPC 一条 3–4 段的小故事（他年轻时跑掉的那条鱼 = 点子 2 的"传说鱼"），完成后给他一个专属鱼竿或称号 | 复用现有对话链路，加分阶段条件 | `entity/FishermanEntity`、`guide/` | 中 |
| **15** | **自动钓鱼日志** | 结束时给玩家一份 txt/markdown 的"我的钓鱼史"（首次钓到的鱼、最大纪录、里程碑日期），可导出发群 | 从图鉴 + SavedData 生成文本 | 新命令 `/atl log` | 小 |

### 8.2 如果只挑三条：我推荐 1 + 2 + 4

| 选它 | 理由 |
|---|---|
| **#1 水下的信息** | 它把"盲抽"变成"读水"，是唯一能从根本上改变**每一竿**体验的一条，而且提示"那儿有鱼"会让玩家自发产生选点行为（= 掌控感） |
| **#2 跑了的大鱼** | 成本不高但**专治钓鱼游戏最大的情绪损失**：断线现在只会让人烦躁，改成"留下一条线索"后，烦躁变成执念 —— 这正是"故事"的来源。它还天然和 #12 传说鱼、#14 老柯剧情连成一条线 |
| **#4 鱼情日报** | 最便宜的"每日回归"钩子：一句话指向真实生效的条件，玩家照着去就能钓到，学会之后就不再需要这句话 —— 它同时是**教学工具**和**习惯养成器** |

## 10. 发散（第三轮）：Minecraft 才是这个 mod 的护城河

> 用户 2026-10-02 追加："继续想，依旧发散思维，**这可是 mc 的 mod**。"
>
> 这一轮的出发点变了：前两轮想的是"**一个钓鱼游戏**该怎么做好玩"，
> 但 MC mod 有一件别的钓鱼游戏**永远做不到**的事 ——
> **它能用方块、维度、红石、村民、附魔、药水、其他 mod 来表达**。
> 所以这一轮专门从"MC 平台特性"反推，看哪些点子**只有做成 MC mod 才成立**。

### 10.0 三个 MC 独占的杠杆

| 杠杆 | 别的钓鱼游戏做不到的 | 本 mod 现在用了吗 |

### 10.5 让别的 mod 能接进来（#50–#51）

### 10.6 这一轮我最想做的三条

> ⚠ **一个必须先讲清的工程前提**（我核对了代码）：
> 现在的 `WaterBody.detect(ServerLevel, BlockPos)` 是**按生物群系标签**判定的
> （`biome.is(IS_RIVER)` / `IS_OCEAN` / `IS_DEEP_OCEAN` / `IS_SWAMP` / `IS_BEACH`），
> 加上"y<55 + 附近有洞穴方块"这一条自定义规则；
> 代码里**没有任何** `FluidState` / 熔岩 / 气泡柱的处理（搜 `LAVA` / `BubbleColumn` 零命中）。
> 所以 ㉝ 岩浆钓鱼、㉟ 气泡柱、㊱ 含水方块这三条都要先给 `WaterBody` **加一层"方块/流体"判定**，
> 再谈鱼种。这一层加好之后，㉞/㊲ 也跟着好做 —— 它是这一组的公共前置。

| 选它 | 理由 |
|---|---|
| **#33 岩浆钓鱼** | 它是**最"MC"的一条**：别的钓鱼游戏永远做不出"在下界岩浆里钓鱼"。而且它几乎不需要新系统 —— 水体判定、鱼种数据、图标生成器、图鉴、商店**全都是现成的**，只是多一条"熔岩"水体与 2–3 条鱼 |
| **#44 鱼鳞药水** | 它把钓鱼**接回 MC 的主循环**（探索与酿造）。玩家从此有理由"专门去钓某种鱼来酿酒"，而不是"钓到什么卖什么" |
| **#47 玩家的钓台影响手感** | 它把**建造**变成钓鱼的一部分 —— 这是 MC mod 独有的杠杆。玩家搭完码头就在那儿钓，是"我的钓位"最有力的形式 |

> 与前两轮合并看：§8 解决"看见鱼"、§9 解决"手法与地形"、
> **§10 解决"这是 MC"** —— 三条线加起来，这个 mod 就有了别的钓鱼游戏给不了的东西。

### 10.7 这一轮明确不做

| 项 | 结论 | 原因 |
|---|---|---|
| 下界/末地**独立维度传送**去"钓鱼世界" | ❌ | 造维度是另一个量级的工程，而且会把玩家从主世界抽走 |

| 让鱼变成"可繁殖出属性更好的后代" | ❌ | 与"品质由窝料/饵料决定"的定案冲突，会变成数值养殖 |
| 硬依赖某个特定 mod（如某个烹饪 mod） | ❌ | 只做**标签/数据包**式联动，保持可服务端单装（`docs/09` 的零冲突原则） |

### 11.2 三句话总结

1. **§1–§6** 补的是**结构**：时间、钓位、纪录、性格 —— 让现有内容有骨架；
2. **§8–§9** 补的是**灵魂**：看见、学会、留下痕迹 —— 让它从"抽奖"变成"钓鱼"；
3. **§10** 补的是**身份**：岩浆钓鱼、玩家钓台、鱼鳞药水、数据包加鱼 ——
   这些是**只有 MC mod 才做得到**的东西，也是这个 mod 在众多钓鱼 mod 里能被记住的理由。

**做的顺序**：结构 → 灵魂 → 身份。前两轮里一半的点子都要用到 §3 那套服务器级存储，
而身份里最省力的几条（㉝ 岩浆钓鱼、㊹ 鱼鳞药水、㊸ 喂动物、51 烹饪标签）
只依赖**已有的**鱼种数据、图标生成器、水体判定与标签基建 —— 随时可以插队做。
