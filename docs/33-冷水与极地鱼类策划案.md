## 1. 要解决的三件事

1. **冷水/高寒水域现在没有专属鱼种** —— 想加鱼，得先能判断"这片水是冷的"；
2. **极地群系（`frozen_*` / `snowy_*` / `ice_spikes` / `grove` / `frozen_peaks`）一条专属鱼都没有** —— 我判断**值得加 10 种**，理由：它能一次打开"冰钓 + 极地探索"这一整片新玩法，而且现有 28 种里没有任何一条能吃下这块场景；
3. **兑换列表要跟着更新** —— 新鱼会改变档位池，而兑换（红鱼线 / 金渔轮那两条）是按档位卡门槛的；用户点名要**把模组附魔书放进兑换**。

## 2. 水域怎么判断（技术方案）

### 2.1 现有的判定（`WaterBody.detect`）

已有：**河流 / 湖泊 / 海洋 / 深海 / 洞穴**。两条已知设计：

- **洞穴判定排在群系判定之前**，而且**不看水深**（否则"深水=洞穴"那条老路会被带回来）；
- **深海继承海洋鱼种**（不然深海用台钓竿一条鱼都没有）。

所以新水体**不能另起一套**，只能在这套之后加"温度/高度"这一层过滤 —— 否则洞穴、深海那两条规则会互相打架。

### 2.2 新增三种"冷水类"水体

| 新水体 | 判据 | 为什么这样定 |
|---|---|---|
| **高寒湖** `ALPINE_LAKE` | 水体 = 湖泊 **且**（`Y ≥ 120` **或** 群系 ∈ `#anglertackle:alpine`） | 高山湖的本质是"高度 + 冷"，单看群系会漏掉"雪线以上的普通山地湖" |
| **冷水溪流** `COLD_STREAM` | 水体 = 河流 **且**（群系基础温度 ≤ 0.2 **或** 群系 ∈ `#anglertackle:cold_streams`） | 溪流本来就是河流；"冷"用**温度**判最省事，不用维护一长串群系名单 |
| **极地水** `POLAR` | 水体 ∈ {河流, 湖泊, 海洋} **且** 群系 ∈ `#anglertackle:polar` | 极地横跨河/湖/海三种水体，所以它是**叠加**在现有水体上的标签，不是替代 |

**双保险原则**（关键）：

- **自定义群系标签**（`data/anglertackle/tags/worldgen/biome/*.json`）—— 可控、数据包能改、和现有的
  `has_fishing_spot` / `has_wild_camp` / `has_fisherman_hut` 是同一套做法；
- **群系基础温度**（`Biome#getBaseTemperature`）—— 自动覆盖"没被列进标签但确实很冷"的群系
  （比如模组/数据包新增的群系），不用逐个补。

两者取**或**：标签管精确，温度管兜底。

### 2.3 结冰水面（极地必须先想清楚）

`frozen_river` / `frozen_ocean` 的水面**是冰**，浮漂落不下去 ✗。三个选项：

| 方案 | 说明 | 我的建议 |
|---|---|---|
| A 排除结冰水面 | 极地只在未结冰的水域能钓 | 最省事，但极地可用点位很少 |
| B **冰钓**：在冰上"开洞" | 用鱼竿（或新道具）在冰面开一个洞，洞口水体算**极地水**；洞口会缓慢回冻 | ★ **推荐** —— 这才是极地该有的玩法，也和"寒冷"主题自洽 |
| C 无视冰面直接钓 | 与视觉不符 | ✗ |

**B 的机制细节（一期先做最小版）**：对冰面右键 → 变成"钓鱼孔"（水方块 + 周围冰）→ 在孔上抛投按极地水判定 → 若干分钟后回冻。

### 2.4 落点与检查器

- `fishing/WaterBody.java`：新增三个枚举 + 判定分支（判定顺序：洞穴 → 深海 → **极地** → 高寒湖 → 冷水溪流 → 原有）；
- 三个新群系标签 JSON；
- `FishSpecies.buildPool()`：把新水体接进"水体 × 竿型"过滤；
- `tools/check-water-body.js`：它的"96 种组合"会涨到 ~150+，**必须同步扩**（否则新水体没鱼也报绿 ✗）；
- 新机制各配断言 + 负例（仓库规矩：每个改动都要能证伪）。

### 3.4 三条防止"加了一堆没人钓"的原则

1. **一条鱼 = 一个场景或一个机制**（新水体 / 新玩法 / 新任务线 / 新料理），否则就是池子稀释；
2. **档位分布要填空白**：按现有 28 种的分布算目标值，新加的档位比重不超过现有同档的 30%；
3. **⚠ 池子稀释是硬约束**：鱼种一多，**现有鱼的出没率会下降** ✗ —— 每次加鱼都必须
   同步检查 `buildPool` 的权重与咬钩下限，并跑一次 `check-water-body.js`（它守"每个水域每种竿型都有鱼"）。

## 7. 风险与坑（动手前先看）

1. **冰面**：极地水面结冰 → 不解决就没法抛投（§2.3）；
2. **极地群系稀少且难到**：`has_fisherman_hut` / `has_fishing_spot` 的群系标签要**补极地**
   （否则玩家跑过去连钓位都没有 ✗）；
3. **池子稀释**（§3.4）：加鱼必须同步调权重，否则"新鱼没人见过、老鱼也变少了" ✗；
4. **检查器组合爆炸**：`check-water-body` 的"96 种组合"会涨到 150+，漏扩就是假绿 ✗；
5. **档位兑换耦合**：红档池一变，红鱼线兑换的门槛就要复核（§4）；
6. **数值平衡**：新增 21 条鱼（6+10+5）会让"抽到目标鱼"的概率明显下降 →
   建议**每期只上一批**，每批上线后按实测微调一次 `buildPool` 权重。

# 8. 冰钓（用户 2026-10-08 定案）

> **用户原话（要点）**：
> · 通过**凿冰镐**右键**任何种类冰面**形成**冰洞**；
> · 使用**鱼竿右键冰洞**，可以**精准抛入洞下水域**；
> · **冰镐对冰洞再次右键**使其变为**碎冰**，一段时间后变为**浮冰**；
> · 在冰洞钓鱼的**鱼线磨损提高 100%** —— "这意味着有条件的玩家可以通过**自行挖掘出大片水域**避免这种损耗"；
> · 但因为冰洞范围不大，**在冰洞抛竿**可以保持原来的**咬钩下限与上限时间**，并**获得额外的 1% 金红总爆率**；
> · 对于**不使用冰洞的抛竿**，**咬钩等待下限和上限时间延长 50%**、**降低 1% 金红总爆率**；
> · **仅适用于"非高山且常年覆冰"群系**，其他地方不会因为形不形成冰洞影响什么。

## 8.1 方块状态机（三形态，**冰洞不会自动回冻**）

```
原版冰面（ice / packed_ice / blue_ice / frosted_ice）
   │ 凿冰镐右键
   ▼
冰洞（本模组方块）—— 水面，可抛投；**不会自己回冻**（用户定案）
   │ 冰镐右键
   ▼
碎冰（本模组方块）
   │ 闲置 M 分钟（默认 5）
   ▼
浮冰（= 原版 packed_ice）
   │ 闲置 K 分钟（默认 10）
   ▼
原版冰（ice）—— 回到最开始，可以再凿
```

**实现要点（零存储、零方块实体）**：

- 每个状态方块在**放置/转换时**自己排一个"到点执行"的调度（`level.scheduleTick`）✓ —— 到点把自己替换成下一形态 ✓；
- **冰洞没有回冻调度** ✓：它只会在被冰镐再次右键时变成碎冰 ✓（用户定案"不会回冻"）；
- 碎冰 → 浮冰 → 冰 的两段延时都来自配置项 ✓（调参器可改）；
- **破坏规则**：冰洞/碎冰被玩家直接挖掉时按原版冰处理（掉冰），但不允许用它刷水/刷冰 ✗（破坏时不给额外掉落）；
- **美术零成本**：冰洞用原版水 + 冰的组合；碎冰用冰的破损变体；浮冰直接用原版 `packed_ice` ✓。

## 8.2 新物品：凿冰镐

| 项 | 设计 |
|---|---|
| 类型 | 独立工具（走现有 `FishKnifeItem` 的模式 ✓，不进六槽配件） |
| 右键**冰面** | 生成冰洞（消耗 1 点耐久 + 碎冰粒子/音效） |
| 右键**冰洞** | 变成碎冰（同样消耗耐久） |
| 右键**碎冰/浮冰** | 无效果（避免刷） |
| 配方 | **4 铁锭 + 2 木棍**（用户定案，仿铁镐）：上排三格铁 = 镐头，第二排「木棍 · 铁 · 木棍」= 加固 |
| 耐久 | 建议 250，凿一次扣 1（可在调参器改） |

## 8.3 抛投：精准入洞

- **鱼竿右键冰洞** → **不走视角抛物线** ✗，直接把浮漂放到**洞中心的水面** ✓（"精准抛入洞下水域"）——实现上是一条**独立的落点路径**（复用现有"落水钉死水体"的逻辑，只是落点由方块给出）；
- 洞下水体判定 = **POLAR（冰下）** ✓，**但前提是群系本身在 `#anglertackle:ice_fishing` 且非高山** ✓
  —— ⚠ 2026-10-08 用户当场纠正了初版："**如果有人运冰到非极地群系你又如何**"：
  只看洞的话，"把冰运到平原挖个洞"就能钓北极鳕 ✗。
  所以**洞只是入口**（决定你从哪下钩），**"这里是什么水"仍然由群系说了算** ✓
  （和现实一致：温带池塘里冻的那块冰不会把水变成北冰洋）。
  洞内那三条数值（咬钩不变 / 金红 +1% / 线损 ×2）照旧生效 —— 它们是"从洞里下钩"的代价与好处，
  与群系无关 ✓；把冰搬到温带只亏不赚（多花钱、多磨线、还钓不到极地鱼）；

# 9. 本轮施工顺序（用户 2026-10-08："不止做极地鱼，本轮计划 20 条可以都加，顺序可以拟"）

## 9.1 ⚠ 读完 `WaterBody.java` 后的设计修正：三个新判定改成「叠加修饰」，不做成新水体

**原设计**（§2.2）是给 `WaterBody` 加三个枚举值。**读代码后我改成"修饰符"**，理由有三条，每条都能对上现有实现：

1. **继承关系会被破坏** ✗ —— 现在 `matches()` 里有一条**深海继承海洋**的特判（"近海鱼本来就会游到远海"，
   而且是"不然台钓竿在深海无鱼可钓"的补救）。极地横跨河/湖/海，如果做成新水体值，
   就得给**每一个**旧水体补一条继承规则，越补越乱；
2. **老的检查器会大面积失效** ✗ —— `check-water-body.js` 守的是"水体 × 竿型 × 竿上限 × 咬钩下限 = 96 种组合
   每种都有鱼"。把水体枚举从 6 个改成 9 个，等于把它的判据整片换掉；
3. **语义上也更对** ✓ —— "高寒湖"本来就是"湖泊 + 冷"，"极地"本来就是"任意水体 + 极地群系"，
   它们是**修饰**而不是**另一类水体**。

**改后的做法**：

```
水体本体（6 个，不动）：河流 / 湖泊 / 沼泽 / 海洋 / 深海 / 洞穴
叠加修饰（3 个，新增）：
  极地      = 群系在 #anglertackle:ice_fishing 且不在 #anglertackle:alpine
  高寒湖    = 水体是湖泊 且（y ≥ 配置值 或 群系在 #anglertackle:alpine）
  冷水溪流  = 水体是河流 且（群系基础温度 ≤ 配置值 或 群系在 #anglertackle:cold_streams）
```

鱼种那边**多三位掩码**（极地 / 高寒湖 / 冷水溪流）；出鱼判定 =
`本体.matches(掩码) || 修饰命中且掩码含该修饰位` ✓ —— **普通鱼种自动继续出现在这些水域里** ✓
（高山湖里当然也能钓到普通湖鱼 ✓），新鱼种则只声明自己属于哪个修饰 ✓。

## 9.4 每批上线后必做的一件事：**调权重**（防池子稀释）

新增 k 条鱼后，同一水域里原有鱼的出现率会变成 `N / (N + k)`（N = 原有鱼种数）：

| 水域 | 原有 | 加完 | 原鱼出现率变化 |
|---|---|---|---|
| 湖泊（加高寒湖 2 条） | 6 | 8 | 16.7% → 12.5%（**−25%**）✗ |
| 河流（加冷水 3 条 + 巨暹罗鲤） | 5 | 9 | 20% → 11.1%（**−44%**）✗ |
| 深海（加远洋 2 条） | 2 | 4 | 50% → 25%（**−50%**）✗ |

**做法**：每批上线后跑一次 `buildPool` 的分布检查（把每个水域每个档位的"平均咬钩等待时间"打出来），
把新鱼压到"稀有但可遇"的位置，**老鱼的出现率下降不超过 25%** ✓。

> ✅ **第 1 批实测（2026-10-08）**：修饰是**叠加**的 ⇒ 稀释只发生在**命中修饰的水域**里，
> 普通河流/湖泊一条老鱼都没被稀释（这是"修饰"相对"另开一种水体值"的额外好处）。
> 两条修饰水域的实测（按种类数，`check-water-body.js` 第 ⑩ 节每次构建都算）：
>
> | 水域 | 老鱼 | 总 | 老鱼占比 | 专属鱼 |
> |---|---|---|---|---|
> | 高寒湖 | 11 | 13 | **84.6%** ✓ | arctic_char / whitefish |
> | 冷水溪流 | 17 | 20 | **85.0%** ✓ | rainbow_trout / burbot / taimen |
>
> 都远在 75% 下限之上，所以**不需要压权重** ✓。上面那张"河流 −44%"的表是**旧设计**
> （当时打算把冷水鱼做成所有河流都会出的普通鱼）留下的估算，改成修饰之后不再适用。
> 真正还要盯的是**第 4 批的深海**：远洋 5 条里只有 2 条进深海，而深海原本只有 2 条 ——
> 那一批上线前必须按本节重算一次。

**把这条验收变成断言**：`check-water-body.js` 第 ⑩ 节 —— 每个修饰水域算出
"本体能进的鱼 vs 只认该修饰的鱼"的比例，**低于 75% 直接报红**；
配负例 `water-dilution`（往冷水溪流多塞 3 条专属鱼 → 必须红）。

> ⚠⚠ **但极地水不适用这条**（用户 2026-10-08 一句话纠正）：
> "**极地群系要是极地鱼不多钓什么鱼**" —— **极地水本来就该以极地鱼为主** ✓，
> 那不是稀释，那就是那片水域的身份。拿"老鱼占比"去量极地是**拿普通水域的尺子量另一个环境** ✗
> （我第一版就是这么写的，跑出"冻洋老鱼只剩 35.7%"还当成问题报上去了）。
> 极地的判据换成两条（`check-water-body.js` 第 ⑪ 节）：
> ① **每个本体都有 ≥6 种鱼可钓**（冻河/冻洋/雪原湖…）；② **常见档保底**
> （至少一条极地鱼最高档 ≤ 蓝，否则新手拿木竿/铁竿在极地钓不到东西 ✗）。
> 负例：`polar-no-common-tier`。
> **推论**：也因此**不需要**给"深海巨物"加本体门槛 ✗（那本来是为了压稀释才想的办法）。
