## 0. 为什么值得做

排行榜是"**静态的过去**"（谁曾经钓过多大的），比赛是"**正在发生的事**"（这一小时谁在赢）。
多人真正的乐趣在后者 —— 而且它**完全不碰钓鱼手感**，全部逻辑都在服务端。

**一句话**：服务端开一场限时赛 → 大家照常钓鱼（**不需要报名、不需要换装备**）→ 结束时全服广播名次 + 发鱼币。

## 1. 赛制（三选一，也可让服主在开赛时指定）

| 方案 | 计分 | 好处 | 坏处 |
|---|---|---|---|
| **A. 最重一尾**（推荐）| 这一场里**单尾最重** | 一杆翻盘 ✓ 戏剧性最强 ✓ 与"排行榜"同一套数据 ✓ | 前 8 分钟可能"没成绩"（要等一条大的）|
| B. 总重量 | 期间所有鱼重量之和 | 一直在动、一直在追 ✓ | 变成"钓得多"而不是"钓得大"⇒ 与 mod 的"手感"主题偏 |
| C. 金红尾数 | 只数金档(4)/红档(5) | 与高档鱼强相关 ✓ | 红鱼本来就稀 ⇒ 多数场次 0:0 收场 ✗ |

**推荐 A**，理由：本模组的核心乐趣是"**遛一条大鱼**"，A 正好把这件事变成比赛；
而且它的记分与 `Leaderboard.Board.HEAVIEST` **完全同源**，不需要新机制 ✓。

## 2. 开赛与参加

| 项 | 方案 | 说明 |
|---|---|---|
| 开赛 | `/atl contest start [分钟] [赛制]`（**需要 OP** —— 它影响全服玩法，属于"明显影响平衡"那一类 ✓）| 不填则用配置默认（默认 30 分钟 / 赛制 A）|
| 自动开赛（可选，第二阶段）| 配置 `contestAutoEveryMinutes`（0 = 只手动）| 服主想做成"每晚 8 点一场"就填 1440 之类的值 |
| 结束 | `/atl contest stop`（OP）；到时间**服务端自己结束** ✓ | |
| **参加方式** | **全员自动参加**（不报名）—— 开赛后**任何人钓到的鱼**都自动计入 ✓ | 理由：报名 = 玩家忘了报 ✗ / 中途加入要不要算 ✗ / "在旁边看着的人"最扫兴。自动参加把这三个问题一次消掉 ✓ |
| 旁观/新加入 | 中途进服的玩家**从加入那一刻开始计**（前面的不算，也不需要他做什么）| |

## 3. 计分（服务端，零新增上报）

- 挂钩点：**上鱼成功那一帧**（与图鉴记账、排行榜记分**同一处**：`FishingManager.onCatch`）⇒ 天然服务端权威 ✓
- 一场比赛的成绩表 = `Map<UUID, 最好的一尾>`（A 赛制只需保留"当前最好"一条 ✓ 内存占用与人数同阶）
- **并列**：重量**完全相同**（同一 `float`）时按**先钓到**的排前（用时间戳兜底）✓
- **不计**：断线跑掉的鱼（只有真上鱼才算）、比赛开始之前钓的、观战者
- 数据存在**世界级 SavedData**里（`anglertackle_contest`），格式：赛制 / 开始与结束时刻 / 成绩表
  ⇒ **服务器重启后比赛继续**（剩余时间按绝对时刻算 ✓），老存档没有这份文件 = 没有比赛 ✓

## 4. 展示与结算

| 时机 | 表现 |
|---|---|
| 开赛 | 全服公告一条：`§6[垂纶] 钓鱼比赛开始！§f赛制：最重一尾　时长：30 分钟` |
| 赛中查询 | `/atl contest`（**无权限** ✓）⇒ 打印：赛制 / 剩余时间 / 自己当前名次与成绩 / 前三名 |
| 赛中"我超过记录了"| **不刷屏** ✗（只在结算时公告一次）—— 中途每上一条大鱼都广播会变成骚扰 |

| 之后 | 成绩**留在** `/atl contest last` 里可查（下一次开赛才覆盖）|
| 界面 | 排行榜界面加一页"**本场**"（复用同一套渲染 + `UiLayout`）—— 第二阶段做 |

**称号**：第一版**不做**（新物品 = 新贴图 + 配方 + 语言键的连锁；玩家图鉴/等级已经够表达"你厉害"）✗

## 5. 奖励（走现有鱼币系统，不造新物品）

| 名次 | 奖励（默认，可调）| 说明 |
|---|---|---|
| 第 1 名 | `contestRewardFirst` = **300 鱼币** | 约等于两条金档鱼 ⇒ "值得参加"但不至于让人靠比赛发财 |
| 第 2 名 | **150** 鱼币 | |
| 第 3 名 | **80** 鱼币 | |
| 参加奖 | **无** ✗ | 有参加奖就会出现"开小号挂着"的刷法；而"自动参加"本来就不需要补偿 ✓ |

- **单人存档也能开**（自己跟自己比）⇒ 不设"最少人数"门槛（`contestMinPlayers` 默认 **1**）✓
- 参与者少于 3 人时：只公告实际存在的名次（1 人也公告，写明"本场只有 1 位参赛者"）

## 6. 边界与坑（逐条给处理）

| 坑 | 处理 |
|---|---|
| 0 人参加 | 结算时如无成绩 ⇒ 公告"本场比赛无人上鱼"（不是静默 ✗）|
| 中途有人退出游戏 | 成绩按他**已经钓到的**保留（他的鱼是真钓的）✓ |
| 服务器重启 | 存的是**绝对结束时刻** ⇒ 重启后继续跑剩余时间 ✓（SavedData 跟着存档 ✓）|
| 专用服务器 / 离线服 | 按 UUID 记分、按当前名字显示 ✓（离线服的成绩按社区信用处理，与排行榜同一口径 ✓）|
| 同一个人开两个账号 | 与排行榜同一处理：按玩家计，不额外反小号 ✓ |
| 不同维度同时钓 | 都算（比赛不限定维度；要限定的话是一行配置）|
| 比赛期间管理员改了时长 | 以**开赛时定下的结束时刻**为准（改配置不影响正在进行的这场 ✓）|
| 两场比赛重叠 | `/atl contest start` 在已有进行中的比赛时**拒绝**并提示剩余时间 ✓ |
| 断线/崩服那一尾 | 只在"上鱼成功"那一帧计入 ⇒ 崩在这一帧之前就不算 ✓（不能补记）|
| 性能 | 每场上鱼只做一次"比较+可能替换"⇒ O(1)，不做每 tick 遍历 ✓ |

## 7. 配置项（`[contest]` 组，全部可热改）

| 键 | 默认 | 含义 |
|---|---|---|
| `defaultMinutes` | `30` | 不填时长时用多少分钟（**游戏时间**：服务器真的跑了多久）|
| `defaultRuleMode` | `0` | 默认赛制：**0 = 最重一尾** / 1 = 总重量 / 2 = 金红尾数（⚠ 落地时从 `heaviest` 字符串改成下标 —— 调参器只认数字与布尔）|
| `minPlayers` | `1` | 低于这个在线人数就不开赛（默认 1 = 单人可玩）|
| `rewardFirst` / `rewardSecond` / `rewardThird` | `300 / 150 / 80` | 名次奖励（鱼币）；**没有参加奖** |
| `autoEveryMinutes` | `0` | 0 = 只手动开赛；>0 = 每 N 分钟自动开一场（也要过 `minPlayers`）|
| `announceTop` | `3` | 结算时公告前几名（1~10）|

## 9. 检查器与负例（交付时必须一起给）

| 断言 | 反例（必须红）|
|---|---|
| 计分挂钩点**只有一处**（与图鉴记账、排行榜同一处）| 在别处再记一次（同一尾鱼记两遍）|
| 比赛数据是**世界级 SavedData**（跟存档走、重启后继续）| 改成内存静态量（重启即丢）|
| 结束时刻是**绝对时刻**，不是剩余 tick | 存"剩余秒数"（重启后计时不准）|
| 开赛/停赛**需要 OP**，查询**不需要** | 把 `contest` 加进 `OP_ONLY`（查询也锁住 ✗，违背用户"指令默认无门槛"）或反之 |
| 结算奖励**只发一次**（重复结算不能重复发钱）| 去掉幂等标记 |
| 重叠开赛被拒 | 允许两场同时跑 |
| 公告条数 == `announceTop`，且无成绩时不静默 | 0 人时不说话 |
| 界面的数字全部来自配置（不许写死）| 手册写死"30 分钟"|
