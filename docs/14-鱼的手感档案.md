# 14 · 鱼的手感档案（Fight Profile）

> 📌 **开工必读** —— 本文件是《垂纶》策划族的一员。动手前先读 `docs/CONVENTIONS.md`（协作规则 + 每轮自我暗示）与 `docs/接力.md`（接手须知）；项目记忆只认 `docs/` 下的文件。

> **你的要求**：
> 1. 不同品种的鱼（特指高级鱼）**手感要不一样**——游得快断线狠的要**趁疲劳期拉杆**；挣扎时游得快但疲劳期拉回也快；另一种游得慢但**线黄得快**
> 2. 上钩后**移动键变成控杆**：**正拉**对鱼体力削减少些但鱼线红得慢些，**反拉**反之，**垂直拉**（中立）是正常状态——类似"不做就不错，没有倾向"
> 3. 鱼的**左右拉倾向**也是手感的一部分：有的冲刺很快，有的左右变向频繁
> 4. **低级鱼可以不做区分**，但高级鱼必须有
> 5. **高级鱼上钩后的拉拽速度普遍比低级鱼快**——让玩家一眼判断这是不是大货
>
> **补充定案（按键）**：**左键按住 = 收线，松开放线；咬钩时左键 = 提竿**（2 秒内不提竿 → 鱼逃离，扣鱼线 + 扣饵料，**不扣鱼竿**）；**A / D = 控杆方向**。
> 代码状态：✅ 已实现并通过构建（`FightProfile` + 控杆三方向 + 疲劳期 + 冲刺/变向/假动作）

## 1. 控杆方向系统（★ 新增核心机制）

钓鱼进入对抗后，**WASD 不再移动玩家，而是操控鱼竿**：

| 按键 | 动作 | 含义 |
|---|---|---|
| **A / D** | 向左 / 向右压杆 | 与鱼的挣扎方向构成"正/反"关系 |
| **W / S** | 抬杆 / 压杆 | 垂直方向 = 中立 |
| 不按 | 垂直（中立） | 正常状态 |

### 1.1 三种关系与数值

```
设鱼的挣扎方向为 f ∈ {左, 右, 直冲}，玩家压杆方向为 p ∈ {左, 右, 垂直}

  正拉（p == f）      → 顺着鱼的方向拉：安全但磨得慢
  中立（p == 垂直）    → 不做就不错，没有倾向
  反拉（p == -f）      → 逆着鱼的方向拉：快但危险
```

| 关系 | 鱼体力削减 | 张力上涨 | 断线风险 | 玩家定位 |
|---|---|---|---|---|
| **正拉** | **×0.65**（少） | **×0.50**（慢） | 低 | 稳住慢慢磨，最安全 |
| **中立**（垂直） | **×1.00** | **×1.00** | 中 | 不做就不错 |
| **反拉** | **×1.50**（多） | **×1.40**（快） | 高 | 速杀，但必须随时准备放线 |

> **设计要点**：正拉和反拉**不是"对/错"，而是"安全但慢 vs 快但危险"的取舍**。
> 没有免费午餐（正拉不加快体力削减），也没有必错选项（反拉不是惩罚）——
> 这正是你说的"类似不做就不错，没有倾向"的延伸：三种都有用，只是场景不同。

### 1.2 与"疲劳期"的配合

```
鱼的冲刺（sprint）周期：
  ┌─ 常态（60% 时间）──┐┌─ 冲刺（爆发型 25% 时间）─┐
  │  可正拉 / 中立       ││  必须放线（张力飙升）      │
  └────────────────────┘└──────────────────────────┘
                    ↑
              冲刺后必然进入【疲劳期】（stamina 低于阈值 + 2 秒）

  疲劳期特征：
    · 拉拽速度 ×1.35（鱼拉得慢了）
    · 张力上涨 ×0.80（更安全）
    · 鱼体力回复 = 0（无法回气）
    → 【反拉的最佳窗口】：此时反拉 = 体力削减 ×1.5×1.2，且张力风险被疲劳期抵消
```

**爆发型鱼的玩法循环**（比如鲨鱼、金枪鱼）：

```
冲刺 → 全放线（线红但不断）
  → 疲劳期 → 反拉猛收（体力狂掉）
    → 鱼恢复 → 再冲刺 → 循环
```

这就是你说的"**游得快断线狠就需要趁疲劳期拉杆**"。

## 2. 手感档案（FightProfile）字段

每条鱼都有一张手感卡，存在鱼类 JSON 里（数据驱动，加鱼不用改代码）：

```json
"fight_profile": {
  "archetype":          "burst",     // burst / erratic / sluggish / steady
  "pull_speed":         1.9,         // ★ 拉拽速度倍率（高级鱼普遍 > 低级鱼）
  "pull_speed_fatigue": 1.35,        // 疲劳期拉拽速度倍率
  "sprint_duration_s":  [2.2, 3.0],  // 冲刺持续时长范围
  "sprint_interval_s":  [4.0, 6.5],  // 冲刺间隔范围（越小越凶）
  "turn_interval_s":    [2.5, 4.5],  // 左右变向间隔范围（越小越神经质）
  "fake_out_chance":    0.05,        // 假动作概率（预告一个方向实际反方向）
  "tension_gain":       0.95,        // ★ 张力上涨倍率（>1 = 线黄得快）
  "stamina":            180,         // 鱼体力上限
  "fatigue_threshold":  0.30,        // 低于此比例进入疲劳期
  "fatigue_duration_s": 2.0,         // 疲劳期时长
  "stamina_regen":      0.02         // 不挣扎时回气速度（被渔轮阻尼抑制）
}
```

### 2.1 四种原型（archetype）

| 原型 | 核心特征 | 玩家该怎么做 | 对应鱼 |
|---|---|---|---|
| **burst 爆发型** | 拉得极快、冲刺狠、变向少 | **趁疲劳期反拉**，冲刺期全放线 | 灰鲭鲨、蓝鳍金枪鱼 |
| **erratic 神经质** | 左右变向频繁、有假动作 | 紧跟预告方向，正拉求稳 | 斑点雀鳝 |
| **sluggish 黏液型** | 拉得慢，但**张力涨得快**（线黄得快） | 全程正拉/中立慢慢磨，**不能急** | 幽渊盲鲟 |
| **steady 均衡型** | 各项中庸 | 视情况切换 | 湖鲈、虹鳟、黄金鲤 |

### 2.2 十种鱼的手感档案（完整表）

> **注意 `pull_speed` 一列**：低级鱼普遍 0.6–1.0，高级鱼 1.6–2.2 —— 这就是你要的"**高级鱼拉的速度普遍比低级鱼快**"。

| 鱼 | 品质 | 原型 | **拉拽速度** | 疲劳期 | 冲刺时长 | 冲刺间隔 | 变向间隔 | 假动作 | **张力上涨** | 体力 | 手感一句话 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 沙丁鱼 | 白 | steady | **0.6** | ×1.2 | 0.5s | 6.0s | 5.0s | 0% | ×0.85 | 60 | 几乎不用管，随便拉 |
| 河流鲫鱼 | 白 | steady | **0.7** | ×1.2 | 0.6s | 5.5s | 4.5s | 0% | ×0.90 | 80 | 新手教程鱼 |
| 蓝鳃太阳鱼 | 绿 | steady | **0.9** | ×1.25 | 0.8s | 5.0s | 4.0s | 0% | ×0.95 | 100 | 略有反抗 |
| 湖鲈 | 绿 | steady | **1.0** | ×1.25 | 0.9s | 4.5s | 3.8s | 0% | ×1.00 | 120 | 标准基准 |
| 虹鳟 | 蓝 | steady | **1.2** | ×1.30 | 1.2s | 4.0s | 3.2s | 3% | ×1.05 | 150 | 开始需要看节奏 |
| 斑点雀鳝 | 蓝 | **erratic** | **1.3** | ×1.30 | 1.0s | 3.5s | **1.6s** | **12%** | ×1.05 | 160 | **左右乱窜**，假动作多 |
| 黄金鲤 | 紫 | steady | **1.5** | ×1.30 | 1.6s | 3.0s | 2.8s | 5% | ×1.10 | 220 | 力气大但规律，是"耐力战" |
| 幽渊盲鲟 | 金 | **sluggish** | **1.6** | ×1.15 | 1.2s | 4.5s | 3.5s | 0% | **×1.45** | **450** | **线黄得飞快**，游得不快但超耐久 → 必须正拉慢磨 |
| 灰鲭鲨 | 金 | **burst** | **2.0** | **×1.45** | 2.2s | 5.5s | 3.0s | 5% | ×1.15 | 320 | 冲刺凶、疲劳期回拉快 |
| 蓝鳍金枪鱼 | 红 | **burst** | **2.2** | **×1.50** | 2.8s | 4.0s | **1.4s** | **10%** | ×1.20 | 520 | 最高难度：又快又乱又耐 |

### 2.3 三种典型玩法的对比（用来验证"手感真的不一样"）

**① 幽渊盲鲟（黏液型）——"线黄得快"**
```
拉拽速度 1.6（不快）但张力上涨 ×1.45
→ 你一反拉，张力条瞬间冲到红区
→ 正确解法：全程【正拉】，慢慢磨 450 点体力（要 2–3 分钟）
→ 考验耐心，不能贪
```

**② 灰鲭鲨（爆发型）——"趁疲劳期拉"**
```
拉拽速度 2.0，冲刺 2.2 秒一次
→ 冲刺期张力飙升，必须放线（放线 2 秒）
→ 冲刺后进入疲劳期：拉拽 ×1.45、张力 ×0.8、鱼不回气
→ 正确解法：疲劳期【反拉】猛收，能把 320 点体力打出成吨伤害
→ 考验节奏感
```

**③ 蓝鳍金枪鱼（爆发 + 神经质）——两者叠加**
```
拉拽 2.2 + 变向间隔 1.4 秒 + 10% 假动作
→ 方向提示几乎每 1.4 秒就变，还有假动作骗你
→ 正确解法：正拉保命为主，只在明确的疲劳期反拉
→ 考验反应 + 判断
```

## 3. 低级鱼"不做区分"的落地

你的要求是"低级鱼可以不用什么区分"，所以我给低级鱼做了**参数收敛**：

| 品质 | 处理 |
|---|---|
| 白 / 绿 | 全部 `steady` 原型，变向间隔 ≥ 3.8s，假动作 0%，张力倍率 0.85–1.0 —— **手感几乎一样，闭着眼也能拉上来** |
| 蓝 | 开始有差异：虹鳟是"稳"，雀鳝是"乱" |
| 紫及以上 | **必须有明显差异**：四种原型各有代表，且参数拉开 |

**白鱼的存在意义**：让新手在**不需要看屏幕**的情况下也能钓上来，把注意力留给"抛投"和"提竿"这两个基础动作。

## 4. 高级鱼"拉拽速度更快"作为难度信号

`pull_speed` 从白的 **0.6** 一路升到红的 **2.2**，这是**两倍以上的差距**。

**玩家的实际感受**（其他参数相同的前提下）：

| 拉拽速度 | 玩家-鱼距离变化 | 体感 |
|---|---|---|
| 0.6 | 即使收线也只能勉强维持距离 | "这条鱼好轻" |
| 1.0 | 收线能明显拉近 | "正常" |
| 1.6 | 收线时距离几乎不降，鱼在往回拽 | "有点拉不动" |
| 2.2 | 不收线时距离飞速增长，逼近逃生线 | "**这是大货！**" |

所以你设计的这个判据非常有效：**鱼一上钩，玩家 2 秒内就能从"拉不拉得动"判断稀有度**，而不需要看任何 HUD。

### 4.1 金 / 红两档的手感修正（2026-10-05 定案）

**用户发现的问题**："发现金档和红手感可能没有差距，游速体力都一样。"

根因是**结构性的**，不是数值没调：`FightProfile` 是**按鱼种**存的快照，而档位是**这一条个体**的事 ——
所以同一条鱼（比如大西洋鲑）抽到金档还是红档，除体重与经济价值外手感完全一样。
档位那条底数曲线（`tierSpeedBase = 1.12`，`1.12^档`）本身只把金红拉开 **12%**，等于感觉不出来；
而**体力池**（`fishStaminaMax`）压根没有档位因子（有的只是 `tierStaminaResist` 那条**抗消耗**线，每档 ×1.18）。

**用户定的口径**：金档游速 **−16%**、体力不变；红档游速 **+5%**、体力 **+50%**。

| 档位 | 游速倍率（底数 × 修正） | 体力池 |
|---|---|---|
| 白绿蓝紫（0~3） | 1.00 / 1.12 / 1.25 / 1.40 —— **一字不动** | 不变 |
| 金 4 | 1.57 × **0.84** = **1.32** | **不变**（×1.00） |
| 红 5 | 1.76 × **1.05** = **1.85** | **×1.50** |

金红之间的游速差距因此从 12% 拉到 **40%**。

**四个旋钮**（都在调参器里，`tools/gen-gameplay-config.js` 是数据源）：
`tierGoldSpeedScale = 0.84`、`tierGoldStaminaScale = 1.0`、`tierRedSpeedScale = 1.05`、`tierRedStaminaScale = 1.5`。

**落在哪两处**（只动移速与体力，冲刺/变向/张力涨速一概不碰）：

1. `FishSpecies.tierSpeed(档)` = 底数曲线 × `tierFeelSpeedScale(档)` ——
   游速只有一个映射，所有消费点（张力、拉拽、漂被拖动、"线被拽远"）自动跟着走，
   **不许在消费点再乘一次**（双重计算会把金档变成 1.32 × 0.84 ≈ 1.11）。
2. `FishingSession` 咬钩组装手感档案处：`fishStaminaMax = profile.stamina() × tierFeelStaminaScale(档)` ——
   体力池是**咬钩那一刻**定死的上限，全流程只有这一处赋值。

档位在组装处只算一次（`hookedTier`），体力池与挣扎节奏（`fishTier`）共用它 ——
两处各算一遍就会漂移，那正是历史上"测试饵出绿鱼却有 7 轮挣扎"那类事故的根因。

守着它的是 `check-tier-feel.js`（四个旋钮数值、金红差距 ≥35%、修正只对 4/5 档、
消费点无双重计算、`fishStaminaMax` 只有一处赋值）+ 5 个负例。

> ⚠ 已知代价：红档体力池 ×1.5 之后，长体力鱼会更磨 ——
> 巨骨舌鱼 520 → **780**，北非胡子鲇 / 蓝鳍金枪鱼 420 → **630**，大眼海鲢 400 → **600**。
> 如果实测觉得"遛太久"，优先动 `tierRedStaminaScale`（调参器可热改），不要动游速。

### 4.2 力竭的鱼必须收得回来（2026-10-06 修）

**用户反馈**："有时候鱼即使力竭了但依然收线回拉不过来，收不收都一个游速，有时候却不会出现这个问题。"

这是**两个毛病叠在一起**，都不是崩，是"数值上的死角"：

**① 距离结算里，鱼拽可能永远压过收线。**
第 6 节的模型是 `距离 += 鱼拽 − 收线`：

```
鱼拽（挣扎）= 0.055 × pullSpeed × tierSpeed(档) × (疲劳 ? 疲劳倍率 0.5 : 1)
收线        = 0.22 × 渔轮的 pullStruggle（休息时用 pullIdle）
```

渔轮的 `pullStruggle` 只有 1.08（手线轮）～1.95（水滴轮），**磨损还会把它压低**
（见底配件被降级，`check-worn-part-stats.js` 守这条）。于是一条红档幼鲨
（3.625 × 1.85 × 0.5 × 0.055 = 0.184/格每tick）仍然拽得过一个磨损的手线轮（0.22×0.3 = 0.066）——
"力竭"只剩一个 HUD 标签，线照样往外走。全组合扫描（27 条鱼 × 金红两档 × 5 个渔轮 + 3 个磨损档）
里，**432 组有 82 组**是这样。

**② 力竭的鱼还在冲刺，把窗口切成碎片。**
疲劳标记的**续期**条件是 `!sprinting`，而冲刺的触发只判"在挣扎 + 冷却到点" ——
一条力竭的爆发型鱼（褐鳟 `sprintIntervalSec 2.6`）每 2.6 秒冲一次、每次 1.6 秒，
冲刺期间疲劳不能续期，于是刚点亮就熄灭。用户日志里的 `疲劳` 与 `-` 交替出现就是这个。
一半以上的 tick 它按"没疲劳"算满拽力。

**修法**（两条一起才有效）：

| 改动 | 位置 | 效果 |
|---|---|---|
| 力竭的鱼**不再冲刺** | `FishingSession` 冲刺段 `if (fishStruggling && !fatigued)` | 体力一旦掉到阈值以下，疲劳标记再也断不了（回气本来就被疲劳挡住），力竭窗口是**连续的** |
| 力竭期**收线保底** | `fatiguedReelMinGain = 0.05` 格/tick | 与轮子好坏**无关**：力竭时收线一定 ≥1 格/秒 |

保底是"玩家的正确操作必须永远有正反馈"这条原则的第三次落地
（前两次是张力那边的 `minReelGainRatio`：收线涨势保底 25%、中立**永远在落**）。

**改完之后的性质**（`check-reel-stall.js` 第 ③ 节逐条断言）：

- 力竭 + 收线：432/432 组**一定回收**（含见底轮子）；
- 没力竭 + 收线：138/432 组仍然是**鱼拽得过轮子** —— 拉锯没被抹平，
  "先扛住、等它力竭再抢线"依然是唯一打法；
- 力竭窗口连续（不再被冲刺打断）。

**日志**：张力轨迹从 `tick|张力|净变化|鱼拉|输入|阶段|疲劳|僵持`
扩成 `…|距离|收线速度|鱼拽速度|僵持` —— 这个症状发生在**距离**上，
以前那份轨迹里根本看不到"收不动"的证据。

### 4.3 红档体力基准下限（2026-10-06 定案）

**用户观察**："有些红鱼似乎体力基准连 200 都没到。"

对。能出红档的 **11 种鱼**里有三种基准不到 200：

| 鱼 | 体力基准 | 红档占比 | 红档实际（×1.5） | 等效体力（÷抗磨 2.29） |
|---|---|---|---|---|
| 蓝宝石雷龙鱼 | 130 | **100%**（台钓唯一的红鱼） | 195 | **85** |
| 虎鱼 | 120 | 29%（最大那批个体） | 180 | **79** |
| 孔雀鱼 | 60 | 29% | 90 | **39** |
| 对比：草鱼（蓝档 220，抗磨 1.39） | | | | **158** |

"遛多久"看的是 `体力池 ÷ tierStaminaResist`（抗磨每档 ×1.18，红档 2.29 **除**在扣体力公式里），
所以那三条"红档"鱼比一条普通草鱼还软 —— 档位只剩个名头。

**定案（用户选的口径）**：给**所有红档鱼**设体力**基准下限** 200 ——
新旋钮 `tierRedStaminaMin = 200`，咬钩时 `基准 = max(基准, 下限)`，**然后**再乘
`tierRedStaminaScale`（1.5）。所以默认下限的红档鱼实际是 **300**。

- 只对**红档**生效：金档的虎鱼（120）原样不动（`redStaminaFloor` 第一句就是 `if (tier != 5) return baseStamina;`）；
- 顺序（先抬下限、再乘倍率）是有意的：两个旋钮各管各的，调一个不会把另一个吃掉；
- 三条小鱼的等效体力：85 → **131**、79 → **131**、39 → **131**。

> 想让"红档一定比草鱼硬"（等效体力 > 158），把 `tierRedStaminaMin` 提到 **280** 左右即可（调参器热改）。

守它的：`check-tier-feel.js` 第 ⑤ 节 —— 旋钮数值、只对红档生效、以及**反向断言**
"至少要真有一条红档鱼的基准低于下限"（否则这条下限就是装饰，得删掉或确认鱼种数值被改过）；
外加 2 个负例（下限失效、下限没接上）。

### 4.4 力竭期的张力修正（2026-10-06 定案）

**用户原话**："加一个鱼力竭时张力涨速再乘 0.85，张力回复再乘 1.15。"

力竭是"反拉的最佳窗口"（§1.2），这段时间线也应该更安全 —— **涨得更慢、落得更快**：

| 方向 | 修正 | 落点 |
|---|---|---|
| 收线的张力**涨速** | **×0.7** | 收线分支的净涨势（`delta + 鱼拉`，钳过 25% 保底之后）再乘它 |
| 中立/放线的张力**回复** | **×1.35** | `recoverMult` 在力竭时再乘它（回落更快） |

两个都是**再乘**，不是替换：

- 涨速那一层，控杆关系里的力竭 `×0.80`（`tensionMult`）原样保留 → 力竭期收线的实际涨速
  是 `0.80 × 0.7 = 0.56`（同向控杆对比非力竭）；
- 保留原有的力竭期扣力 `drainMult × 1.20`（力竭时扣鱼体力更快）。

> 数值沿革：2026-10-06 先定 0.85 / 1.15，同一天用户实测后改成 **0.7 / 1.35**
> （"把力竭时张力回复到 1.35，涨速 0.7"）—— 两个都在调参器里，随时可改。

**边界（`check-reel-stall.js` 第 ④ 节逐条断言，27 条鱼 × 4 个档位 × 3 条线 = 324 组）**：
力竭时涨速**严格更慢**、回落**严格更快**，但收线仍然**一定在涨**（>0）、中立仍然**永远在落**（净变化严格为负）——
"更安全"不等于"没有张力"。

> 顺带修掉一个**假数据**：张力轨迹里的"净变化"列取错了采样点（`beforeClamp` 是在结算**之后**
> 取的），于是它恒为 `+0.0000`、"僵持"计数一路数到 31 —— 用户 2026-10-06 那份日志里满屏
> `+0.0000` 就是这个。现在改成结算**之前**取（`beforeTension`），那一列才有意义。

### 4.5 力竭**什么时候开**：全局阈值倍率（2026-10-06 追加）

**用户反馈**："我在游戏中实际感觉力竭更难拉了。"

查他那一局的日志（`张力算式` 每 20 tick 一条，共 31 条）：**全部**是
`力竭涨速×1.00 / 回复×1.27` —— 也就是说**那条鱼一次都没进疲劳**，
§4.4 的两个系数根本没参与。那局是铂金银龙鱼、档 5、`体力池 450.0 = 基准 300.0 × 1.50`。

根因是 §4.1 的**体力池 ×1.5 把"进疲劳的比例"落在了 1.5 倍的绝对值上**：

| | 改之前 | ×1.5 之后 |
|---|---|---|
| 池子 | 300 | **450** |
| burst 型进疲劳阈值（34%） | 102 | **153** |
| 体感 | 扣到 102 就亮【疲劳·快拉】 | 要扣到 **153** 才亮 —— "它明明快没劲了却怎么都不力竭" |

**新增旋钮** `fatigueThresholdScale`（默认 **1.0** = 与鱼种值一致，不动任何既有手感）：
`进疲劳比例 = min(1.0, 鱼种阈值 × 倍率)`。

| 倍率 | steady | sluggish | burst | erratic |
|---|---|---|---|---|
| ×1.0（默认） | 0.300 | 0.280 | 0.340 | 0.320 |
| ×1.25 | 0.375 | 0.350 | **0.425** | 0.400 |
| ×2.0（上限） | 0.600 | 0.560 | 0.680 | 0.640 |

也就是说：**想让力竭来得更早、更容易看到"快拉"窗口，把它调到 1.25 左右**，
不用去动体力池厚度（那是另一个手感维度）。
结果**夹在 1.0**——倍率 >1 不会变成"一咬钩就力竭"，要那个效果请直接改鱼种的 `fatigueThreshold`。

> 另一个更直接的选择：把 `tierRedStaminaScale` 从 1.5 降到 1.25~1.35（红档整体不再"1.5 倍磨"）。
> 两个旋钮管的是不同的事：**一个管"多厚"，一个管"多早"**。

守它的：`check-reel-stall.js` 第 ④b 节（旋钮数值、接线、四个策略的阈值都从源码解析出来验算、
拉到上限也不会 ≥1）+ 1 个负例。

### 4.6 中立时的最小净回落（2026-10-06 追加：张力"下降好慢"）

**用户反馈**："现在感觉张力下降好慢，所有时候。"

**他日志里的原文**（铂金银龙鱼 红档）：

```
张力=120.50 输入=放线 回复×1.46 delta=-2.342 鱼拉=1.650   ← 放线：47 点/秒，很快
张力= 97.30 输入=放线 回复×1.46 delta=-2.342 鱼拉=1.650
```

放线一档没问题（−2.34 点/tick = **47 点/秒**）。慢的是**中立**那一档：

| | 数值 |
|---|---|
| 中立回落 | `idleLoss(0.35) × 回复(1.46) = 0.511` 点/tick |
| 鱼的拉力 | `1.650` 点/tick |
| 鱼拉被削到 | `min(1.650, 0.511 × 0.90) = 0.46`（"最多削到回落的 90%"） |
| **净回落** | `0.46 − 0.511 = **−0.05 点/tick ≈ 1 点/秒**` ✗ |

从红区退回白区要 **50 秒**，玩家的感受就是"条子几乎不动"。而且**任何时候**都这样 ——
因为"鱼拉最多削到回落的 90%"是**按比例**削的：

> ⚠ **所以调 `idleLoss` 几乎没用** —— 回落涨多少，鱼就按比例多削多少，净额永远是那 10%。
> 真正能动的是"允许鱼削掉多少比例"（`maxFishSlowdown`）或下面这条绝对下限。

**修法**：新增 `idleFallFloor`（默认 **0.30 点/tick ≈ 6 点/秒**）——
不管鱼多猛、装备好坏，**中立**时每 tick 至少回落这么多：

```
net = min(net, −idleFallFloor)
```

扫描 27 条鱼 × 4 档 × 3 条线 × 力竭/非力竭 = **648 组**，其中 **316 组**在修之前慢于这条下限；
修完全部达标，且"中立永远在落"依然成立。**只作用于中立** —— 放线那一档本来就 −2.34/tick，
不需要也不该被改写。

> ⚠ 代价（知道就好）：原来"干站着不动会被慢慢拖进黄区"的压力会消失（中立一定能回白）。
> 想要那份压力就把 `idleFallFloor` 调回 **0**（调参器热改，0 = 关掉）。
> 想让回落更快就往上调：0.5 ≈ 10 点/秒。

守它的：`check-reel-stall.js` 第 ⑤ 节（旋钮数值、只作用于中立、648 组全扫、"下限不是装饰"）
+ 1 个负例。

## 5. 与配件系统的交互

| 属性 | 谁主导 | 在控杆系统里的作用 |
|---|---|---|
| 回拉速度（常态/挣扎） | 渔轮 | 决定你在三种关系下的**基础收线速度** |
| 体力削减 | 渔轮 60% + 鱼竿 40% | 乘在"正拉 0.65 / 中立 1.0 / 反拉 1.5"之上 |
| 压制阻尼 | 渔轮 | 抑制鱼的 `stamina_regen`（黏液型鱼最怕这个） |
| 张力上限/回复 | 鱼线 60% + 鱼竿 40% | 决定你能不能扛住"反拉 ×1.4 的张力上涨" |

**推导出的装备策略**：
- 打**爆发型**（鲨鱼/金枪鱼）→ 需要**高张力上限 + 高回复**（线好），因为要吃冲刺和反拉
- 打**黏液型**（盲鲟）→ 需要**高体力削减 + 高阻尼**（渔轮好），因为这是一场耐力战
- → **两种鱼需要两套装备**，这是刻意的：让"六槽改装"有真实的策略价值
