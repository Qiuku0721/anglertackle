## 1. 落地方式（三个结构同一套）

| 项 | 取值 | 为什么 |
|---|---|---|
| `terrain_adaptation` | **`beard_thin`** | 小屋已经是它；帐篷这种轻结构也是它最合适（不削山头、只垫底） |
| 模板池 `projection` | **`terrain_matching`**（现在小屋是 `rigid`） | **这条才是"宛如镶嵌"的关键**：村庄的房子用的就是它，部件会跟着地形起伏；`rigid` 是"整块硬贴"，地形一有坡就出现凹陷/台阶 |
| `project_start_to_heightmap` | `WORLD_SURFACE_WG` | 起点贴地表 |
| `step` | `surface_structures` | 与村庄同层 |
| 生物群系 | 见 §2 | 决定"能不能长在水边" |

> ⚠ 只改 `terrain_adaptation` 不改 `projection` 是不够的 —— 用户看到的"凹陷下去排开泥土"
> 主要是 `rigid` 的整块投影在坡地上留下的空隙；`beard_thin` 只负责补底，不负责贴合。

## 2. 生成位置与密度

| 结构 | 生物群系标签 | spacing / separation | 依据 |
|---|---|---|---|
| 野外营地 `wild_camp` | 新建 `#anglertackle:has_wild_camp`（陆地为主：森林/平原/针叶/稀树/丛林/沼泽…） | **30 / 8** | 村庄是 34/8，"大一丢丢" |
| 钓位 `fishing_spot` | 新建 `#anglertackle:has_fishing_spot`（**水边**：河流、沙滩、石岸、沼泽、红树林沼泽、海洋浅水） | **22 / 6** | "刷新在水边，密度可以稍微大点" |
| 渔人小屋 `fisherman_hut` | 现有 `#anglertackle:has_fisherman_hut` 不动 | 34 / 8 不动 | 只改"镶嵌"（§1） |

**钓位"一个台阶在水面上"怎么保证**：结构本身只有 3 格宽、2 格高，台阶（云杉台阶×2）在一端；
把生物群系限制在**水边群系**（河流/沙滩/石岸/沼泽）＝生成点必然在岸线附近，
配合 `WORLD_SURFACE_WG` 把起点贴到**地表**，于是靠水那一端的台阶自然悬在水面上，
其余落在陆地上。这是数据包能表达的极限 —— 数据包没有"必须紧邻水"的谓词。

## 3. 战利品（用户给的四个档位概率）

**木桶**（4 个）→ `anglertackle:chests/wild_camp_tackle`：鱼竿 / 鱼线 / 鱼钩 / 渔轮 / 拟饵 / 鱼饵。
**装饰罐**（3 个）→ `anglertackle:chests/wild_camp_fish`：**一条鱼**。

⚠ **一个容器至多刷 2 个 mod 物品**（用户 2026-10-05 追加）。落地口径：
木桶只有一个池子、`rolls = uniform(1, 2)`，所以**最多两个 mod 物品**（不是"多个池子各抽一次"——
那样一箱能出 4~5 件，正是要避免的）。概率是**每件**都按同一套权重抽，不是"整箱按权重选一次"。
守门里对这条有专门断言（把池子数 × rolls 上限算出来，必须 ≤ 2）。

| 档位带 | 目标概率 | 权重（SCALE=10，和为 1000） |
|---|---|---|
| 白绿（档 0–1） | **71.5 %** | 715 |
| 蓝紫（档 2–3） | **25 %** | 250 |
| 金（档 4） | **3 %** | 30 |
| 红（档 5） | **0.5 %** | 5 |

> 金档从 4.5% 调成 **3%**、差额给白绿（用户 2026-10-05："没红的东西就把金爆率调到 3%"）。

## 3.1 哪些东西进池子（用户 2026-10-05 定案）

| 类别 | 进不进 | 档位来源 |
|---|---|---|
| 鱼线 | ✅ | `PartStats.line(..., N)`，1 起算 |
| 拟饵 | ✅ | `PartStats.lure(N)`，1 起算 |
| 鱼饵 | ✅ | `new BaitItem(N, …)`，**0 起算** |
| **鱼竿** | ✅ | **要补档位**（现在 `rod("wood_lure_rod", …)` 辅助函数注册，没有档位参数） |
| **渔轮** | ✅ | **要补档位**（现在 `PartStats.reel(...)` 不带档位；`partTier = 0` = "无档位"）。⚠ 渔轮**有品质**，补的时候按已有的 Rarity 与注释阶梯：手线轮白 / 纺车轮绿 / 鼓轮蓝 / 水滴轮紫（注释写"紫档，收线型"）/ 大型纺车轮金（注释写"金档，绞盘型"） |
| **鱼钩** | ❌ **不弄**（用户明确） | — |
| 调试物品 | ❌ | `lure_test_red`、`fisherman_spawn_egg` 进黑名单 |

⚠ 补档位时必须过"两套刻度"这一关：`partTier` 是 **1 起算**、`BaitItem.tier` 是 **0 起算**、
渔轮/鱼钩现在都是 **0 = 无档位**。任何新增读档位的代码都必须先归一到"白=0 … 红=5"，
否则症状是"某些档的分布不对"而**没有任何报错**（AGENTS.md 里两次事故都是这个）。

⚠ **两套档位刻度必须先归一**（AGENTS.md 反复强调的那条）：
鱼饵 `BaitItem.tier` 是 **0 起**，配件 `PartStats.partTier` 是 **1 起**。
生成器里统一换算成"白=0 … 红=5"再分带，不然后果是"某些档的分布不对"而没有任何报错。

**鱼那条**：从 `FishSpecies` 的档位范围（`W_G{0,1}` / `G_B{1,2}` / `B_P{2,3}` / `G_B_P{1,2,3}` / `G_R{4,5}` / `R{5}` / `P_G{3,4}` / `P_G_R{3,4,5}`）
取**与该带相交**的鱼，并用 `set_components` 写 `FISH_DATA`（`species` / `length_cm` / `weight_kg` / `tier`，
与老柯小屋红鱼池同一套写法）；体重取该鱼 kg 区间的中点，体长取 docs/03 鱼种表的体长区间中点
（**不发明数字**：docs/03 是数值真源，中点是它与"随机一条鱼"最自然的对应）。

**老柯小屋那张表**：本次**不动**（用户只要求改它的"镶嵌"）。两张表概率不同的原因要在文档里写清楚，
免得以后有人以为是不一致。

## 4. 守门（打算新增 `tools/check-sites.js`）

1. 三个结构的模板池 `projection` 都是 `terrain_matching`、`terrain_adaptation` 都是 `beard_thin`（"镶嵌"这条要被机器守住）
2. 两个新结构的 NBT 存在，且尺寸与 `参考资料/结构/` 里的源文件一致（没被手改坏）
3. 容器：木桶/装饰罐**都挂了各自的 LootTable**，且 NBT 里**没有残留 `Items`**（残留 = 玩家开箱先看到造物品再被表覆盖）
4. 战利品表：四个带的权重反算出来必须落在 70 / 25 / 4.5 / 0.5（±0.3 点），且引用的物品/鱼都真实存在
5. 鱼那条表**只有一个鱼条目**且 `set_components` 写了 `tier`（不写就是"普通品质鱼"）
6. 密度：营地 spacing < 34（村庄）且 > 钓位 spacing（"前者比村庄大一点、后者更密"）
7. **至多 2 个 mod 物品**：`Σ(池子数 × rolls 上限)` 必须 ≤ 2（见 §3 的口径）
