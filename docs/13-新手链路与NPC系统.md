## 1. 渔人小屋（结构）

### 1.1 生成规则

| 项 | 值 |
|---|---|
| 结构 ID | `anglertackle:fisherman_hut` |
| 生成群系 | **`#minecraft:is_river`（强制）**，以及沼泽/湖泊岸边为可选变体 |
| **贴水要求** | 结构原点必须**距离水源方块 ≤ 6 格**；生成时向水面方向对齐，不足则放弃该次生成 |
| 生成间距 | `spacing = 34` 区块，`separation = 9` 区块（比原版村庄稀疏，保证"发现"的惊喜感） |
| 生成高度 | 地表（水面以上 1–3 格） |
| 变体 | 首版 1 种（河流版）；海洋版栈桥 M8 扩展 |

> **可靠性保障**：因为要求"贴水 + 河流群系"，在极端地形（全是干涸河谷）下可能出现某个区域找不到小屋。为此：
> - 追踪罗盘**搜索半径 400 格**；找不到时提示"附近没有渔人小屋，往里走远一点再试"
> - 配置项 `worldgen.hutSpacingChunks` 可调（整合包可以调密）
> - 已生成的小屋在全世界范围内被记录进 `SavedData`，罗盘直接读这份记录（不用每次遍历区块）

**三个踩过的坑（都写进 `tools/check-npc-fisherman.js` 守住了）**：

1. `AbstractVillager` **没有**覆写 `mobInteract`（`WanderingTrader` 和 `Villager` 各自实现了一份）。
   只继承它 → 右键老柯不开界面、不报错、日志里一行都没有，是最难查的那种"看起来装好了"。
2. `AbstractVillager.getOffers()` 在客户端是
   `throw new IllegalStateException("Cannot load Villager offers on the client")` ——
   **抛异常，不是返回空表**。没被 `!isClientSide` 包住就会崩客户端。
3. `AbstractVillager` 有两个 abstract 方法：`updateTrades()` 和 `rewardTradeXp(MerchantOffer)`。
   后者名字像可选钩子，其实是必须实现的。

**台词为什么要一批、而且轮流说**（用户原话："那 NPC 只有这一句话"）：

第一版只在商品为空时回一句"竿子先支好，货我还没备齐……"。反复右键同一个人、
他永远回同一句，NPC 当场就"死"了 —— 台词量是"活人还是告示牌"的分界线，
不是文案细节。现在 10 句，**按顺序轮转**（起点随机，多个小屋的老柯不会同步开口）。

为什么不用随机：10 句里连着抽三次撞上同一句的概率并不低，
玩家的感受和"只有一句话"完全一样。轮流能保证每一句都会被听到。
`check-npc-fisherman.js` 把"台词池 ≥ 6 句""每句都有中英语言键""必须是轮转不是随机"
都断言住了，并有三个对应的负向用例。

台词里第 3 句是**故意放的路标**：`想找我家？拿条鱼配个指南针，它就认路了。`
—— "屋子难找"和"追踪罗盘"这两件事在这里合流，玩家不用翻教程书就知道有这个东西。

## 2. 追踪罗盘（Finding the hut）

### 2.1 合成

```
        ┌─────────────┐
        │  任意鱼 ×1   │  ← 包含：本模组所有鱼 + 原版生鳕鱼/生鲑鱼/河豚/热带鱼
        ├─────────────┤
        │  指南针 ×1   │
        └─────────────┘
              ↓
      ┌────────────────┐
      │  追踪罗盘 ×1    │  可重复使用（耐久 64 次）
      └────────────────┘
```

**"任意鱼"的判定**：同时接受 `#anglertackle:fishes` 标签与 `#minecraft:fishes` 标签。
→ 保证"新手钓到第一条鱼之前也能用原版钓竿先钓条鳕鱼做罗盘"，不会被卡住。

### 2.2 使用

| 行为 | 效果 |
|---|---|
| 右键 | 计算**最近的未访问渔人小屋**，指针持续指向它（不是原版指南针的指向出生点逻辑） |
| 手持时 HUD | 显示一行：`渔人小屋 · 距离 213 格 · 东北方向` |
| 距离 < 32 格 | 提示"就在附近"，并在小屋位置生成一柱**垂直光柱粒子**（只对持有罗盘的玩家可见） |
| 抵达 | 罗盘记录该小屋为"已发现"，之后右键会指向**下一个**未发现的小屋 |
| 找不到 | 提示"400 格内没有渔人小屋了"（不消耗耐久） |
| 耐久 | 每次**成功指向**消耗 1 点；找不到不消耗 |
| 修复 | 追踪罗盘 + 1 鱼币 可修（或直接再合成一个，成本很低） |

### 2.3 为什么不做成"直接传送"

保持"找路"的探索感，也避免破坏多人服务器里"钓点"这个共享资源的意义。罗盘给的是**方向与距离**，不是传送门。

### 2.5 指针是怎么做出来的（以及踩过的坑）

**坑 1：紫黑方块。** 第一版模型写的是 `"layer0": "minecraft:item/compass"`，
想着"引用原版指南针的图就行"。**原版根本没有 `textures/item/compass.png` 这张图** ——
它只有 `compass_00.png` ~ `compass_31.png` 共 32 帧，指针的转动就是在这 32 帧之间切。
`item/compass` 是一个**带 overrides 的模型**，不是贴图。引用一个不存在的贴图 = 紫黑方块。

**坑 2：半径 400 根本不够。** 用户的反馈是"只显示 400 格内没结构"。
这不是"附近真没有"，是**算错了该给多大**：
小屋的 `placement.spacing` 是 **34 区块（=544 格）**，`random_spread` 会在每个
34×34 的网格里随机落一个候选点。玩家到最近候选点的距离最坏约
`spacing × √2 / 2 ≈ 24 区块 ≈ 385 格`；再叠加群系校验失败
（不是每个候选点都落在河流/沼泽/沙滩上）要跳到更远的网格 ——
所以 400 **经常**找不到。改成 1200 才覆盖得住两格的最坏情况。

（好消息：搜索是**一圈一圈往外扩、找到就停**的，所以平时开销取决于
"最近那间有多远"，与上限无关；只有"附近真的没有"时才会走满。）

**做法：** 服务端算位置、客户端算角度。

- `fishing/HutLocator`（服务端）：只对**手持罗盘**的玩家搜；
  两秒一次上限；没移动 16 格不重算；换维度立刻重算；结果变化时才发包。
- `network/HutLocatorPayload`：**发位置不发角度**。发角度的话玩家一转头指针
  就跟不上（服务端不知道你什么时候转头）；发位置，客户端每帧自己算相对角度，
  转身即时跟手 —— 原版指南针也是这么做的。
- `client/ClientHutLocator`：注册 `minecraft:angle` 物品属性。
  属性名用原版的：`ItemProperties.register` 的键是 **(物品, 属性名) 这一对**，
  原版就是这么干的（`COMPASS` 和 `RECOVERY_COMPASS` 各注册了一份），互不干扰。
  这样模型 json 里可以直接写 `"predicate": {"angle": 0.0}`，
  那 33 条 overrides 就能**逐字照抄**原版，不用自己推 32 帧的角度分档。

**角度公式一个数字都没改**，来自 `CompassItemPropertyFunction.getRotationTowardsCompassTarget`：

```
a01   = atan2(dz, dx) / 2π                目标方向
yaw01 = positiveModulo(视朝向 / 360, 1)    玩家朝向
angle = positiveModulo(0.5 - (yaw01 - 0.25 - a01), 1)
```

那两个 `0.5 / 0.25` 是"物品模型坐标系"和"世界坐标系"之间的换算。
凭直觉推一定会差 90° 或 180°，而且**它在游戏里看着还挺合理**，只有拿尺子量才发现反了。

**没做的打磨**：原版对本地玩家还叠了一层 `CompassWobble`（指针平滑转过去而不是瞬移），
稳态值完全相同。想加就在 `ClientHutLocator.angle` 那里加。



**⚠ 「失灵的罗盘」故意没做**：策划案 §2.2 写的修理配方是「追踪罗盘 + 1 鱼币」，
而鱼币**不是物品**（你定的：走独立数据面板），当不了合成材料。
修理路径定下来之前注册它只会得到一个"拿到手没有任何用途"的东西。备选：
「失灵罗盘 + 指南针 → 追踪罗盘」。

**⚠ 耐久 64 写死、没有做成配置项**，这不是偷懒：`Properties.durability()` 在
**物品注册那一刻**就烙进物品实例了，而 NeoForge 配置加载**晚于**所有注册事件 ——
注册期读配置会抛 `Cannot get config value before config is loaded.`（本项目踩过两次）。
事后改一个 int 也改不动已经建好的 ItemStack 上限。所以提供一个改不动的配置键才是骗人。
**搜索半径是真能在运行时读的，所以那个留在配置里。**

**搜索开销（决定默认值 400 的依据）**：`findNearestMapStructure` 的 radius 单位是
**区块**，实现是**一圈一圈往外扩、找到就停**。小屋 spacing 是 34 区块，
所以正常地形下第一两圈就命中，开销和"最近那间有多远"成正比、**与上限无关**；
上限只在"附近真的没有"时才会被走满 —— 那也正是会卡的那种情况。

```
│  🔒 碳氟线                        450 ¤  │
│     需要钓鱼等级 15（当前 11）              │
└──────────────────────────────────────────┘
```
灰色显示 + 锁图标 + 明确写出所需等级与当前等级。**不隐藏**——让玩家知道"升到 15 级有什么等着我"。

## 4. 第一根钓竿（两条路都通）

| 途径 | 说明 |
|---|---|
| **① 自己合成** | 木棍 ×3 + 线 ×1 → **木台钓竿**（与原版钓鱼竿配方相似但**不冲突**：原版是 3 木棍 + 2 线，斜放；我们的是 3 木棍 + 1 线，直放，配方形状不同） |
| **② 找老柯免费领** | 首次对话选项「我是新手，能给我一根竿吗？」→ 送 **木台钓竿 ×1** |

**领取规则（"不重复"）**：
- 每个玩家**只能领一次**，由玩家 Attachment 上的 `receivedStarterRod` 标记控制。
- 竿丢了/坏了**不能补领**（否则会被当成免费刷竿点）。
- 损坏后可以修（见 §5），修理费比合成贵一点点，引导玩家自己做第二根。
- 领取时老柯说一句台词：*"拿去吧，别弄丢了——我可只给一次。"*

## 5. 钓竿耐久归零 → "破损的钓竿"（已定案）

```
    正常钓竿（耐久 > 0）
         │ 咬钩累积损耗（白鱼 −2 … 红鱼 −48 × 材质系数）
         ▼ 耐久 = 0
    ┌──────────────────────┐
    │ 破损的钓竿            │  · 保留：附魔、六槽配件、竿类型
    │ （Broken Rod）        │  · 不能抛竿
    │                       │  · 会显示"需要修理"
    └──────────┬───────────┘
               │ 修理：材料 + 鱼币（按缺失耐久比例）
               ▼
        正常钓竿（满耐久）
```

| 项 | 值 |
|---|---|
| 修理费用 | `缺失耐久 × 0.35 鱼币 + 1 个对应材质锭`（木竿用任意木板） |
| 修理地点 | 任意工作台（用"修理"配方）**或**老柯处（贵 20%，但省材料） |
| 保留内容 | **附魔全部保留**、**六槽配件全部保留**、竿类型保留 |
| 破损竿的外观 | 贴图加裂纹 + 名称显示为"破损的木台钓竿" |
| 为什么不做碎裂 | 合金竿 8000 耐久是长期投资，碎裂会让玩家不敢钓大鱼，与"手感优先、不劝退"冲突 |

**追踪罗盘同理**：耐久耗尽变"失灵的罗盘"，1 鱼币 + 1 铁粒 修复。

## 6. 新手前 15 分钟的完整体验（用来验收这条链路）

```
1. 进游戏，背包里没有竿
2. 合成木台钓竿（3 木棍 + 1 线）——砍树、杀蜘蛛/拆蛛网拿线
   （或者：先不管钓鱼，去找老柯领免费的）
3. 随便找条河，抛竿，钓上第一条河流鲫鱼
4. 用【河流鲫鱼 + 指南针】合成追踪罗盘
5. 跟着罗盘走到渔人小屋，见到老柯
6. 对话 → 领取免费木台钓竿（第二条竿，可以给朋友或备用）
7. 打开商店 → 只有 1 级商品 → 买包蚯蚓
8. 在码头钓鱼椅坐下，开始刷白绿鱼
9. 升到 5 级 → 商店解锁玉米粒/亮片拟饵/倒刺钩 → 第一次"变强"
```

**验收标准**：一个从没看过文档的玩家，靠教程书 + 老柯的台词，能在 **15 分钟内**走完上面 9 步。

## 9. 这一节对应的自检

老柯这一个实体牵扯**五个互不相干的注册表**（物品 / 实体类型 / 实体属性 / 渲染器 / 语言键），
少任何一个的表现都不一样，而且没有一条报错会告诉你"你漏了哪一步"：

| 漏了什么 | 表现 |
|---|---|
| 实体类型 | 刷怪蛋一放就崩 / 报"未知实体" |
| **实体属性** | 实体能生成，但 NaN 血、一出现就倒地（**报错里不提"属性"两个字**） |
| 渲染器 | 实体隐形，但碰撞箱还在（能撞到、能右键，就是看不见） |
| 语言键 | 名字显示成 `entity.anglertackle.fisherman` |
| `mobInteract` | 右键完全没反应（不开界面、不报错、日志无输出） |

所以配了两个检查脚本，并且**都做过负向测试**（故意改坏 → 必须报错）：

- `tools/check-spawn-egg.js` —— 刷怪蛋必须用 `DeferredSpawnEggItem`（不能 `.get()` 提前取值）
- `tools/check-npc-fisherman.js` —— 上面那张表的每一条
- `tools/negtest.ps1` —— 13 个改坏的临时副本，逐个断言检查脚本会红；
  真实源文件全程只读。**第一版 `check-npc-fisherman.js` 有两处假通过
  （在注释里搜到关键字就放行），正是被它抓出来的。**
