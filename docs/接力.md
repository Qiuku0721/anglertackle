## 2. 环境与命令（这台机器的实况）

- 本机没有 `pwsh`，只有 **Windows PowerShell 5.1**：
  `powershell -NoProfile -ExecutionPolicy Bypass -File <脚本>`。
- 当前 shell 跑在 **ConstrainedLanguage** 下：`[System.IO.File]::`、`[Text.UTF8Encoding]::new()`、
  `.Trim()`、`.Substring()` 这类**会报错**。文本操作走 `node -e "…"`（注意引号）或文件工具。
- Gradle：`$env:GRADLE_USER_HOME=.gradle-home`，JDK 在 `.jdk\jdk-21.0.12.1+1`。
  **快车道**：`tools\gradlew.cmd compileJava`（~8-25 秒）、`tools\gradlew.cmd jar`。
  ⚠ gradle 会打一段 file-watcher 堆栈并 `exit 1`，**即使 BUILD SUCCESSFUL** —— 看 stdout 的结论行。
- **整条闸**：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-deploy.ps1 -NoDeploy`
  阶段：0 快照 → 1 构建 → 2 生成器链 → 3 调参器 → 4 全部检查器 + 负例 → 5 部署（`-NoDeploy` 跳过）。
  实测 **180~420 秒**（同一份代码波动很大，是机器负载，不是回归）。
  日志是 **UTF-16LE**：`Get-Content build\gate-xxx.log -Encoding Unicode`。
- **部署**（`D:\mc\...\mods` + `导入用`）需要对工作区外的写权限：
  在本 harness 里就是 `sandbox_permissions: danger-full-access`（会弹一次授权框）。
  部署内容：拷 jar → 删旧 `anglertackle-*.jar` → 拷 `导入用` → 三处 sha256 比对。
  ⚠ 扩展包 `anglertackle-kaleidoscope-1.0.0.jar.disabled` **必须保持禁用**：
  它把 `kaleidoscope_cookery` 声明成 required，没装森罗时会让 FML **崩在加载阶段**。
- 负例引擎：`tools\negtest.ps1`（可 `-Filter 子串` 只跑几条、`-Jobs N` 调并发）。
  内部：`tools/_negtest.js` 建副本（硬链接 + 分片并发）、`tools/_negrun.js` 跑断言（4 路、同检查器串行）。
  ⚠ **变异测试必须用 `stdio: 'inherit' | 'ignore'`**：本机沙箱禁 `'pipe'`（EPERM），
  而它的 `status` 是 `null` —— 把 `null` 当"非零退出"就会把**根本没跑起来**的用例报成"抓到了"。

## 3. 代码地图（`src/main/java/com/whitecobalt/anglertackle/`）

- `fishing/` 钓鱼核心：`FishingSession`（**档位归一化的唯一汇合点 `equippedBaitTier()`**）、
  `FishSpecies`/`FishHabits`（后者是生成物）、手感与抵抗。
- `item/` 物品与档位：`Quality`（**白0 绿1 蓝2 紫3 金4 红5**）、`BaitItem.tier` 同样 0 起；
  ⚠ **配件 / 拟饵 `PartStats.partTier` 是 1 起（1白…6红，0=无档位）**，两套刻度是故意的，
  只允许在 `equippedBaitTier()` 汇合（这里出过两次真实事故，见 `AGENTS.md` §二）。
- `league/` 联赛：`League`(规则/窗口) + `LeagueData`(世界 SavedData `anglertackle_league`) + `LeagueService`。
- `contest/` 比赛：`Contest` + `ContestData`(SavedData `anglertackle_contest`) + `ContestService`。
- `mail/` 邮件：`MailService`（`deliver()` 是**唯一投递入口**）、`MailActions`（白名单动作，**在认领写入之后跑**）、
  `MailReturns`（`toMailboxOrDrop()`：先寄信、邮箱满再掉在脚下）。
- `title/` 称号：`TitleDefs` / `Titles` / `TitleSnapshot`；`client/ClientTitles` + `network/TitlePayload`。
- `client/screen/` 界面：`MailScreen`（正文滚动 + 2px 滚动条）、`UiLayout.wrapCjk`（**别在"拉丁词+中文"之间断行**）。
- `command/AnglerCommands.java`：**每条子指令都走 `lit(name)`**，只有 `lit()` 里允许出现
  `hasPermission(`；要 OP 的只有"改数/发东西"四条（`stage`/`coins`/`resetstock`/`repair`）。
  守这条的是 `tools/check-command-permissions.js`（本地单人存档**永远测不出来**）。
- 配置链：`Config.java`（手写分组 + 生成段）→ `Tuning.java`（getter）→
  `put(flat, "group.key", c.field, counter)`；调参器/校验 schema **只支持数字与布尔**
  （字符串没有载体 ⇒ 例如 `leagueUseRealDays`(bool)、`leagueRuleMode`(int 0..3)）。

## 6. 事故档案（症状 → 真凶 → 修法，别重蹈）

   从 `build/negtest/<某个副本>/tools/_negtest.js` 逐字节恢复。
3. **"字符串在 ≠ 事情在做"**：一天之内栽了 5~6 次（`mail-no-scroll`、`league-no-stats`、
   `xp-silent-at-gate`、`no-wrapcjk`、`link-write-through`…）。
   ⇒ 判据要盯**调用点 / 计算 / 顺序**（下标、调用了多少次、是不是函数体第一条语句），
   不要全文件搜字符串；**注释里提到某个名字**也要先剥注释。

   「负例构造失败」，而闸报「存在漏检的检查脚本」（看起来像检查器抓不到变异）✗。
