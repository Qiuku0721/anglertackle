## 2. 机制（定稿）

| 项 | 规则 |
|---|---|
| 载体 | 每个效果是**原版药水效果**（`MobEffect`）：右上角有图标、有倒计时、等级显示 I/II/III… |
| 来源 | 吃**菜**给。**新效果只在"顶级鱼（金 4 / 红 5）做的菜"上生效**（用户定） |
| 等级 | **由鱼的品质档位决定**：等级 = 鱼的档位（4=金 → IV、5=红 → V），**再按该效果的"至高"封顶** |
| 时长 | ⚙️ 基础时长按材料档位：**普通 3:00 / 优质 5:00 / 顶级 8:00**，**每级 +2:00**（顶级：金 IV→14:00、红 V→16:00；封顶后取封顶级的时长） |
| 同名菜不同级 | **只保留最高级那一份**（等级低的不覆盖、不倒扣）；时长取两者中较长的一个 |
| 一道菜多个效果 | 允许（用户定）：顶级菜 = **新效果 + 该菜型的旧效果**（若有） |
| 互斥 | **爆口 × 空军**：后获得的**顶掉**先获得的 |

> ⚙️ 例：红档（5 级）大西洋鲑做的刺身 → **海洋亲和 V**（14:00 + 2:00 = 16:00）+ 速度 II 30s + 水下呼吸 30s。

### 3.1 爆口 / 空军的门槛口径（定稿）

门槛 **5 kg**（用户："那就降到5公斤"）；判定用**区间中值**（⚙️ 我提的口径，理由见下）：
某条鱼的**各品质档体重区间的中值**决定它归哪一边 —— 于是**每条鱼恰好落进一边**，不会出现两头都不加成的死区。

| 效果 | 判定 |
|---|---|
| 爆口 | 该鱼各品质区间**中值 > 5 kg** → 它的抽取权重 +5% |
| 空军 | 该鱼各品质区间**中值 ≤ 5 kg** → 它的抽取权重 +5% |

覆盖（现有 23 条食用鱼，门槛 5 kg + 中值判定）：**爆口 11 条 / 空军 12 条** ✓ 两边都够用。
（若改回"区间不跨界"，爆口只剩 3 条 —— 那条路已排除。）

> 改口径只需动一处：`effect` 包里判定归类的那个方法。

### 7.2 ⚙️ 几个必须写下来的口径

| 项 | 决定 | 理由 |
|---|---|---|
| 渔运"不承诺占比"的饵 | 先按**当前池子**算出金红占比，再加 3 个百分点 | 直接加会得到 `−1+3=2` 这种"目标"，把路亚原本 20%+ 的金红占比**压到 2%** |
| 渔运的 3 个点在金/红之间怎么分 | 按**组内权重**分摊（一份预算，解 k 时整组同乘） | 与饵料既有的"金红占比精确求解"同一套算法；金红权重不等时不是严格的各 1.5 点 |
| 爆口 / 空军乘在哪一步 | **解完 k、取整之前** | 放 k 之前会被 k 原样除回去（净效果为零）；放取整之后 3×1.05=3（一分不加） |
| 干旱耐受的"下雨加成" | 漏斗 `rainBonusActive`：风暴行者的伤害/速度；钓鱼侧把环境天气钉成降雨 | 本 mod 的雨天加成只有这两处，写成一个漏斗才不会漏 |
| **水下加速挂哪个属性** | **`NeoForgeMod.SWIM_SPEED`**（水里）/ `MOVEMENT_SPEED`（只有两栖的陆地那一半） | 原版水中分支**不读 MOVEMENT_SPEED**：加速度 `f5` 基量写死 0.02，只有 `WATER_MOVEMENT_EFFICIENCY > 0` 时才被拉过去；惯性 `f4` 由 0.8 起算（海豚的恩惠直接 `f4 = 0.96`，这就是它能真加速的原因）。挂 MOVEMENT_SPEED 只会改**客户端 FOV** —— 2026-10-03 用户实测："能看到因为速度变化导致的视野缩放，但实际移速不会变化" |
| 两栖的"潮涌能量" | 在陆地时**直接发** `CONDUIT_POWER` | 原版 `ConduitBlockEntity` 硬编码 `isInWaterOrRain()`，NeoForge 没留事件；而潮涌能量这个效果本身没有水下限制（`MobEffectUtil` 只读 hasEffect） |
| 两栖的"深海探索者" | 陆地给 `MOVEMENT_SPEED × 0.6825 × 效率` | 原版水里 `f4` 从 0.8 降到 0.546，相对速度 ×0.6825；这是**唯一可调旋钮** |
| 明目怎么找"最近" | **一次扫完整个立方体取全局最近**（按 \|dy\| 由近及远扫层 + 层内窗口随最优距离收紧 + 层偏移超过最优距离就收工） | 第一版是"每 tick 扫一层、33 tick 攒一轮、每轮清零"，那个"最近"只是**本轮已扫过那几层里最近的** —— 2026-10-03 用户实测："指引线乱跳，疑似指向多目标但不是最近的"。**挤牙膏式的扫描算不出全局最近** |
| 明目换目标的滞回 | 新目标要**近 ≥3 格或近 ≥25%** 才换；某次扫描落空时保留原目标 | 两块远近差不多的矿会在玩家走动时轮流当"最近"，线就来回抽搐；扫描偶尔落空也不该让线闪一下 |
| 明目扫描的节流 | 有目标时 20 tick 扫一次（相位按实体 id 错开）；一次没扫到就退到 60 tick | 满扫 3.6 万格。有矿时剪枝通常几千次就结束；**没矿（地表）每次都是满额**，所以要退避 |
| 明目扫描范围/频率 | 半径 16、以**眼睛所在的方块**为原点 | 脚下方块与视线差一格多，"最近"要按玩家看到的算 |
| 明目的指引怎么画 | **服务端只报坐标，客户端按鱼线那套画线**（`RenderLevelStageEvent` + `RenderType.lines()`）；主线 + 目标方框 + 沿线的流动点 | 用户 2026-10-03："一个是不算很能清晰地指引方向，二个是粒子多会容易卡顿，建议参考鱼线的渲染方式，做一个由准心指向矿物块的线"。改完**每条线只有一个包、粒子数为零** |
| 明目的发包时机 | 目标变了就发 + 每 20 tick 心跳；效果到期/目标被挖掉发"撤线"包 | 每 tick 发一个包没必要；客户端还有 60 tick 超时兜底，丢包/换维度都不会留下一条指向空气的线 |
| 明目认哪些方块 | NeoForge 通用标签 `#c:ores` | 原版**没有**"全部矿物"这一个标签；通用标签还能带上别的 mod 的矿石 |
| 修饰符的形态 | 瞬态（`addTransientModifier`）+ 每 tick 幂等重算 | 效果条件是动态的（在水里/下雨/在陆地），挂永久修饰符中途不会重算；瞬态不存档，退出重进不会留下永久加速 |
