## 2. 属性合成公式（透明、可调）

```java
// 六个部件的属性合成（服务端计算，客户端只读取结果）
final double tensionCeiling =
      100.0
    * lerp(LINE.ceilingBonus,  0.60)     // 鱼线主贡献
    * lerp(ROD.ceilingBonus,   0.40);    // 鱼竿副贡献
    // lerp(x, w) = 1 + (x - 1) * w   —— 把部件的加成按权重缩放
    // 上限硬钳制在 1.60（你定的倍率上限）

final double tensionGen =
      1.0 * LINE.genCoeff;               // 只由鱼线决定（0.62 ~ 1.00）

final double tensionRecover =
      1.6                                // 基础回复速率（点/tick）
    * lerp(LINE.recoverBonus, 0.60)
    * lerp(ROD.recoverBonus,  0.40);
    // 上限硬钳制在 2.20 → 顶配 3.52 点/tick
    // 从张力 100 掉回白区（55）耗时 = 45 / 3.52 ≈ 12.8 tick ≈ 0.64s
    // 基础配置耗时             = 45 / 1.6  = 28.1 tick ≈ 1.4s

final double pullSpeedIdle =
      0.10 * REEL.pullIdle;              // 上限 1.40 → 0.14 格/tick

final double pullSpeedStruggle =
      0.035 * REEL.pullStruggle;         // 上限 1.40 → 0.049 格/tick
    // 常态 / 挣扎 = 2.86 倍（落在你要求的 2–3 倍区间）

final double staminaDrain =
      1.0
    * lerp(REEL.drainBonus, 0.60)
    * lerp(ROD.drainBonus,  0.40);
    // 上限硬钳制在 1.80 → 大鱼从 40 秒缩到 22 秒
```

> **可调性**：所有权重（0.60 / 0.40）、所有上限（1.60 / 2.20 / 1.80）都写在 `balance.json` 的 `parts.weights` 与 `parts.caps` 里。你玩过之后觉得"鱼竿的存在感太弱"，把竿的权重从 0.40 调到 0.55 就行，不用改代码。

## 4. ② 鱼线（6 档）

| 鱼线 | 品质 | 耐久 | 线长 | 张力上限 | 张力涨速 | 张力回复 |
|---|---|---|---|---|---|---|
| 麻线 | 白 | **50** | 30 格 | ×1.08 | ×0.97 | ×1.05 |
| 棉线 | 绿 | **50** | 35 格 | ×1.20 | ×0.91 | ×1.15 |
| 尼龙线 | 蓝 | **40** | 45 格 | ×1.28 | ×0.95 | ×1.30 |
| 碳氟线 | 紫 | **35** | 60 格 | ×1.64 | ×0.78 | ×1.42 |
| 编织 PE 线 | 金 | **30** | 65 格 | ×2.08 | ×0.64 | ×1.52 |
| 钛合金记忆金属线 | 红 | **30** | 70 格 | ×2.36 | ×0.56 | ×1.78 |
> ⚠ 上表是**实装值**（真源：`ModItems` 里 `PartStats.line(...)` 的字面量，2026-10-05 按用户口径更新）。
> 线长写作 "x 格" 是因为代码里存的是 `x / 30.0` 的倍率（30 格 = 麻线基准）。
> 合成为最终数值时：**张力上限 / 张力回复 = 鱼线 60% + 鱼竿 40%**，再受 `Config` 的 `capTensionCeiling`（默认 ×3.00）等硬上限约束。

**顶配验算**（顶级碳纤线 + 合金竿）：

```
张力上限  = 100 × [1 + (1.36-1)×0.60] × [1 + (1.28-1)×0.40]
          = 100 × 1.216 × 1.112 = 135.2 → 钳制检查：1.352 < 1.60 ✅

若鱼线换成普通 PE 线、竿身也用钻石竿：
          = 100 × 1.198 × 1.112 = 133.2

理论最高组合（若未来加更高档线材）会被 1.60 的硬上限拦住，不会失控。
```

**你说的"能拉鱼的时间更长"换算**：顶配 135 点上限 vs 基础 100 点，意味着红区之前能多承受 **35 点张力**——按收线 +0.9/tick 计算，等于**多 39 tick ≈ 2 秒**的安全拉扯时间；配合 ×2.2 的回复速度，实际能多耗大鱼 30% 以上的时间。

## 5. ③ 渔轮（5 档）

| 渔轮 | 品质 | 回拉（不挣扎） | 回拉（挣扎） | 体力削减 | 压制阻尼 |
|---|---|---|---|---|---|
| 手线轮 | 白 | ×1.08 | ×1.08 | ×1.08 | ×1.07 |
| 纺车轮 | 绿 | ×1.25 | ×1.25 | ×1.25 | ×1.20 |
| 鼓轮 | 蓝 | ×1.45 | ×1.45 | ×1.60 | ×1.45 |
| 水滴轮 | 紫 | ×1.98 | ×1.95 | ×1.40 | ×1.40 |
| 大型纺车轮 | 金 | ×1.64 | ×1.64 | ×2.30 | ×2.50 |

**数值验算（你要求的"差 2–3 倍"）**：

| 渔轮 | 常态回拉 | 挣扎回拉 | 倍率 |
|---|---|---|---|
| 手线轮 | 0.100 格/tick | 0.035 格/tick | **2.86×** |
| 纺车轮 | 0.115 | 0.042 | 2.74× |
| 鼓式轮 | 0.130 | 0.046 | 2.83× |
| 电动轮 | 0.140 | 0.049 | 2.86× |

> **设计意图**：挣扎时回拉速度被压到 **1/3**，所以"等鱼不挣扎时猛拉"成为核心技巧——这正好对应你说的"鱼不挣扎时的回拉速度和挣扎时回拉速度"要有明显区别。玩家学会"看鱼的挣扎节奏收线"而不是无脑按右键。

**压制阻尼**的作用：鱼在不挣扎时会缓慢回气（基础 0.02/tick）。阻尼 ×1.80 时回气降到 **0.011/tick**——意味着用重型绞盘时，鱼几乎不会越拉越有劲，**越拖越虚**。这是"大货专用轮"的价值。

### 5.1 保底体力削减（2026-10-06 新增，渔轮专属）

> 用户定义："拉鱼时每秒最少削减的鱼力，**不受上限限制**。由渔轮提供，根据压制阻尼转化而来。
> 无论渔轮压制阻尼多少，该属性最小值为 5……上限 20。"（追加："转化系数最好取整或 0.5"）

`保底 = clamp(5, 20, 5 + max(0, 压制阻尼 − 1) × 10)`

系数 **×10** 是**倒推**出来的：让金轮（大型纺车轮，阻尼 2.50）正好落在 **20.0** 贴住上限，
同时它是个**整数**（用户要求）；五个轮的梯度也就干净了：

| 渔轮 | 品质 | 压制阻尼 | 保底削减（点/秒） |
|---|---|---|---|
| 手线轮 | 白 | 1.07 | 5.7 |
| 纺车轮 | 绿 | 1.20 | 7.0 |
| 鼓轮 | 蓝 | 1.45 | 9.5 |
| 水滴轮 | 紫 | 1.40 | 9.0 |
| 大型纺车轮 | 金 | 2.50 | **20.0**（贴住上限） |

> ℹ️ 水滴轮（1.40）的保底略低于鼓轮（1.45）—— 因为**阻尼本身就低一点**。
> 这是配件数值的排序问题，不是转化公式的问题；要改就改轮子的阻尼。

**为什么它是独立的第三条线**：收线扣力本来受**单轮额度**限制（`roundDrainCap()` —— 金/红档按
"计划轮数"分摊，额度用尽的那一轮会变成扣 **0**）。保底削减**绕过这个上限**：
只要在收线，每秒至少扣这么多。于是"磨鱼"这件事**一定在推进**，
不会出现"到某个鱼力就不动了"。取的是**较大者**（`max(上限允许量, 保底/20)`），不是相加。

没装渔轮、或者渔轮已经见底 → **0**（用户："装备了渔轮的路亚"才有保底；与"见底配件不再提供加成"同一口径）。

三个旋钮都在调参器里：`reelFloorDrainBase`（5）、`reelFloorDrainPerDamping`（10）、`reelFloorDrainCap`（20）。
守它的是 `tools/check-reel-floor-drain.js`：五个轮的数值逐个复算（数据来自 ModItems 的 damping）、
值域、单调性、接线（取较大者、在单轮上限之后）、以及**提示不重写公式**（必须调用同一个函数）。

### 5.2 收线速率抵抗（2026-10-06 新增，所有鱼都有）

> 用户定义："收线速率高于 1.2 的鱼竿配置（双拉属性，一般由渔轮负责，比如水滴轮 1.9 左右），
> 各个档位的鱼有不同的抵抗：白 5%、绿 10%、蓝 15%、紫 20%、金 25%、红 32%。
> 策略可上下浮动至多 5%；最终影响可由压制阻尼抵消一部分，至多抵消 75%；
> 让金轮大致触碰到转化极限。"

**公式**：`实抗 = 档位基准 × (1 + clamp(−5%, +5%, 策略浮动)) × (1 − clamp(0, 75%, 阻尼抵消))`
其中 `阻尼抵消 = (压制阻尼 − 1) × 0.5` —— 系数 **0.5** 是为金轮倒推的：2.50 → **0.75** 正好贴住上限。

**只对超过阈值 1.2 的那部分打折**（`阈值 + (收线 − 阈值) × (1 − 实抗)`）——
整条打折会在阈值处跳变（1.21 打完折比 1.19 还慢），玩家会觉得"换了好轮子更拉不动"。

| 档位基准 | 白 5% | 绿 12.5% | 蓝 18.5% | 紫 27.5% | 金 55% | 红 **75%** |
|---|---|---|---|---|---|---|

（绿/蓝/紫/金/红 是用户 2026-10-06 定下的新默认值，白档不动。）

| 渔轮（阻尼） | 阻尼抵消 | 红档实抗 | 双拉 1.98 时的实际收线 |
|---|---|---|---|
| 手线轮 1.07 | 3.5% | 72.4% | 1.41 |
| 水滴轮 1.40 | 20% | 60.0% | 1.51 |
| 大型纺车轮 2.50 | **75%**（贴上限） | 18.8% | 1.83 |

旋钮共 13 个（阈值 / 六档基准 / 四个策略浮动 / 每点阻尼抵消 / 抵消上限），工具提示里写的
「压制阻尼」和这里用的是**同一个函数**（`PartComposer.damping`），不会出现"提示变了判定没变"。
守它的是 `check-reel-stall.js` 第 ⑦ 节（数值表 + 阈值处不跳变 + 单调性 + 源码结构断言）。

|---|---|---|---|---|---|
| 木浮漂 | 白 | ×1.00 | 基准 | ✗ | 基准 |

**灵敏度**的作用：影响三段预告（探饵→试探→吞钩）的动画幅度与**提前量**。高灵敏度浮漂会让"试探"阶段更明显，玩家更容易判断"这是小鱼在试，别提竿"——**这是降低误提竿率的配件，不是加伤害的配件**。

> 这也回应了你说的"打窝饵料与鱼漂等做成实体"：浮漂是**六号槽的可换配件**，同时也是**水面上的实体**（有独立的追踪范围与渲染规则，见 `09-原版冲突与渲染优化.md` §4）。

## 9. 铅坠（首版的处理方式）

你选了 6 槽（含浮漂）同时也要铅坠。**首版把铅坠做成"饵料的附属属性"而不是独立槽位**：

| 铅坠 | 归属 | 效果 |
|---|---|---|
| 轻坠 | 拟饵自带 | 下沉慢，停留表/中层 |
| 中坠 | 拟饵自带 | 下沉中速 |
| 重坠 | 拟饵自带 | 下沉快，直达底层 |
| 沉底坠 | 拟饵自带 | 固定在最底层，**配合沉底窝使用** |

→ 想换铅坠就是**换拟饵**（浅层刺激拟饵自带轻坠，振动饵自带重坠）。这样改装界面保持 6 槽不会太挤，同时保留了"重坠打底层"的玩法。

| 拉半天拉不动 | 渔轮（回拉速度） |
| 大鱼越拉越有劲 | 渔轮（压制阻尼）+ 鱼竿（体力削减） |
| 放线了还是断 | 鱼线 + 鱼竿（张力回复速度） |
| 总钓不到大鱼 | 鱼竿（承重上限） |
| 老是提竿太晚 | 鱼竿（窗口）+ 浮漂（灵敏度） |
| 晚上看不见漂 | 浮漂（荧光漂/电子漂） |
| 抛不到远处的深水 | 鱼线（线长） |

> 这张表会**原样放进教程书第三章**——玩家不需要理解公式，对照症状换配件就行。
