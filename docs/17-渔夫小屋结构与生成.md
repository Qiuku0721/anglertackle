## 1. 源文件与现状

| 项 | 值 |
|---|---|
| 你存的文件 | `saves\新的世界 (1)\generated\minecraft\structures\yurenxiaowu.nbt`（9431 字节） |
| 存档时间 | 2026-09-30 22:57 |
| 已导入到 | `src/main/resources/data/anglertackle/structure/fisherman_hut.nbt`（字节完全一致） |
| 导入方式 | `node tools/import-structure.js "<你的 .nbt 路径>"` |

**重新导出后要重跑一次导入脚本。** 它会顺带做四件手工容易漏的事：

1. 目标目录名写成 `structure`（**单数**）。1.20 及以前是 `structures`，
   写成复数**不会报错**，结构就是永远不生成。
   （这个事实是从 `minecraft_1.21.1_client.jar` 数出来的：`data/minecraft/structure/` 下
   1180 个 `.nbt`，没有 `structures` 目录。）
2. 复制完**在原进程里回读校验**（不是调用另一个脚本 —— 见 §4 的沙箱坑）。
3. 断言"字节数一致 / 方块数非零 / 结构里没有实体"。
4. 从结构里**算**出地板层、门坐标、最外侧四列、有没有水，打进日志。
   结构被你改过时，日志里一眼能看出差异，不用再手工数方块。

尺寸 **15 × 13 × 15**（x × y × z），2925 格，48 种方块，**0 个实体**。

| 事实 | 值 | 怎么量出来的 |

**老柯的站位**：`(12.5, 2.0, 13.5)` —— 码头尽头的原木上，脚下一格是实心块
（不是台阶，不用下落），头顶两格空。旁边 [13,3,13] 有盏灯笼。

## 3. 放置方案

用**原版** `minecraft:jigsaw` 结构类型 + 单元素模板池，不写 Java。理由：

- 小屋是**单体结构**（不是拼图村庄），`size: 1` 就够了。
- `project_start_to_heightmap: WORLD_SURFACE_WG` 在河流群系里落到的是**水面高度** ——
  于是小屋地板（y=1）刚好比水面高一格，地基（y=0）落在水面，
  `terrain_adaptation: beard_thin` 把小屋底下垫成一小块岸，
  码头（y=1）正好伸在水面上。**"河边小屋 + 伸向水面的码头"就是这么来的**，
  不需要额外的"找水"代码。
- 群系标签 `#anglertackle:has_fisherman_hut` = 河流 / 沼泽 / 沙滩（已建）。
  只放 `#minecraft:is_river` 不够 —— 河很窄，随机点很容易落到紧邻的岸上群系。

**风险与已知取舍**：河宽通常 8–20 格、小屋宽 11 格，所以有可能生成在
"一侧是水、一侧是陆"的河岸上，也可能整栋压在河心。第一次进游戏要重点看这两种情况。
真到了必须精确"离水 ≤6 格"的时候，再升级成自定义 `StructureType`（那时要写 Java）。

**已落地**（2026-09-30）：

| 文件 | 作用 |
|---|---|
| `data/anglertackle/worldgen/structure/fisherman_hut.json` | jigsaw 结构定义 |
| `data/anglertackle/worldgen/template_pool/fisherman_hut.json` | 单元素模板池（`single_pool_element` + `projection: rigid`） |
| `data/anglertackle/tags/worldgen/biome/has_fisherman_hut.json` | 河流 / 沼泽 / 沙滩 |

结构 JSON 的关键字段（每一个都对着 `JigsawStructure.java` 的 CODEC 核过）：

```jsonc
"step": "surface_structures",
"terrain_adaptation": "beard_thin",        // 小屋底下垫一层地
"size": 1,                                 // 单体结构，不拼图
"start_height": { "absolute": -1 },        // ← 第一号调参旋钮
"project_start_to_heightmap": "WORLD_SURFACE_WG",
"placement": {
  "type": "minecraft:random_spread",
  "spacing": 34, "separation": 9,
  "salt": 1283001                          // 必须各结构不同，否则分布会和别的结构重合
}
```

`start_height: {"absolute": -1}` 是**唯一需要凭手感调的**：`project_start_to_heightmap`
给出的是"水面之上第一格"的高度，`start_height` 会**加**在它上面。
你搭的房子在 y=0 有一层地基、y=1 才是地板，所以往下沉一格正好让地基落在水面线上。
游戏里看着偏高就改成 `0`，偏低就改 `-2`。

## 4. 老柯怎么跟着结构出现

**不写"结构生成后回调"那种代码** —— NeoForge 没有"结构生成完成"事件，
那套路子最后都要 mixin 进 `StructureStart`。改成**把老柯直接写进结构 NBT 的
`entities` 列表**，由 `tools/inject-npc.js` 生成。

### 格式（逐条对着 `StructureTemplate.java` 的读写代码核过）

```jsonc
entities: [                       // List<Compound>，元素类型必须是 10
  {
    "pos":      [12.5, 2.0, 13.5],  // List<Double> —— 元素类型 6
    "blockPos": [12, 1, 13],        // List<Int>    —— 元素类型 3
    "nbt": { "id": "anglertackle:fisherman", "Rotation": [...], ... }
  }
]
```

三个**写错就静默失效**的点：

1. `pos` 必须是 **List\<Double\>**（元素类型 6）。写成 List\<Int\> 读出来是垃圾坐标。
2. `blockPos` 是**必需**的，而且必须是 **List\<Int\>**（元素类型 3）——
   读取代码直接 `getList("blockPos", 3).getInt(0)`，缺了会抛异常。
3. `blockPos` 必须在结构包围盒内。`addEntitiesToWorld` 里有一句
   `if (placementIn.getBoundingBox() == null || placementIn.getBoundingBox().isInside(blockpos))`，
   不在框里就**跳过**，不报错。

另外两条有用的：

- **`nbt` 里不用写 `Pos`**：放置时会被 `pos` 算出的世界坐标无条件覆盖
  （`compoundtag.put("Pos", listtag)`），写了纯属误导。`UUID` 也会被 `remove`。
- **别指望 `finalizeSpawn`**：`StructurePlaceSettings.shouldFinalizeEntities()` 默认是
  **false**，所以 `finalizeSpawn` 不保证被调用。老柯改成在
  `FishermanEntity.adoptSpawnAsHome()` 里"第一 tick 自己把落脚点认领成家"，
  不依赖那个标志位；`/summon` 出来的也一样适用。

### 站位和朝向是算出来的

`inject-npc.js` 不写字面量坐标：把结构按 x 轴切成"小屋那一半 / 码头那一半"，
在码头那半边找"脚下是整块、头顶两格空"的格子，取离小屋重心最远的一个；
朝向 = 从小屋重心指向它（也就是面朝水面）。**幂等** —— 重跑会先删掉旧的同名实体。

所以你改了结构重新存一次，只要：

```
node tools/import-structure.js "<你的 .nbt>"
node tools/inject-npc.js
```

数字会自动跟上，不用回来改文档。

## 5. 战利品箱（**没做**）

结构里有 **8 个箱子**（[2,2,3]、[2,2,4]、以及 y=7 上一排 6 个），
NBT 是 `{"Items":[],"id":"minecraft:chest"}` —— **全是空的**。

⚠ 设计稿（`docs/13` §1.2）写的是"鱼饵 ×4–12、麻线 ×1、**鱼币 ×20–80**、5% 拟饵"，
但**鱼币不是物品**（你定的：鱼币要单独一个数据面板，不要物品化），
箱子塞不进"钱"。所以这一条要么改成别的东西（比如多给几个高级拟饵），
要么做成"打开箱子时给玩家加钱"（要写方块实体/交互代码）。
**这条没动，等你定。**

## 7. 这一节对应的自检

| 脚本 | 守什么 |
|---|---|
| `tools/check-nbt-writer.js` | NBT 写入器**逐字节**正确（判据是"和原文件字节完全一致"，不是"读回来数值对"） |
| `tools/check-hut-structure.js` | 结构路径 / NBT 可解析 / 群系标签 / 结构 JSON / 模板池引用 / 实体的三个坐标字段 / 站位在包围盒内 |
| `tools/check-npc-fisherman.js` | 老柯的注册四件套 + `mobInteract` + `getOffers` 的服务端守卫 + 认领落脚点 |
| `tools/check-spawn-egg.js` | 刷怪蛋必须走 `DeferredSpawnEggItem` |

四个脚本一共配了 **24 个负向用例**（`tools/negtest.ps1`）：把仓库复制到临时目录、
故意改坏 21 处，断言对应检查器每一处都必须报错；另有三棵未改动的对照组必须放行。
真实源文件全程只读。

**为什么 NBT 写入器的判据必须是"逐字节"**：这一层出错的表现是
**结构静默不生成** —— 不报错、日志里没有一行。而且坏法极隐蔽：

- `size` 从 List\<Int\> 写成 IntArray
- 空列表的元素类型从 0 写成 10
- 根标签后面多写一个 TAG_End

这三种在游戏里**表现完全一样**（什么都不发生），只有逐字节比对能挡住。
写这个检查时它当场抓到了一个真 bug：写入器多输出了一个尾字节
（`Compound` 的 payload 自带 TAG_End，根标签后面不该再补一个）。

## 8. 沙箱坑（写给以后的自己）

- **这个环境禁止 node 用管道捕获子进程输出。**
  `child_process.spawnSync` / `execFileSync` 一律 `EPERM`。
  所以"调用另一个脚本再读它的 stdout"这条路**走不通** ——
  `import-structure.js` 第一版就是这么写的，直接挂。
  要做校验只能在同一个进程里 `require`。这就是把解析器抽到 `lib-nbt.js` 的原因。
- PowerShell 的 `Select-Object -First N` 会提前关掉管道，
  让 node 以非零码退出 —— 那是**假警报**，不是脚本失败。
- `.ps1` 文件必须带 UTF-8 BOM（PS 5.1 会把无 BOM 的当 GBK 读），
  而 `edit` / `write` 工具会**抹掉 BOM**。改完 `.ps1` 记得跑一次
  `node tools/ensure-bom.js <文件>`。
- PowerShell **变量名大小写不敏感**：`$Out` 和 `$out` 是同一个变量。
  `negtest.ps1` 里用 `$out` 接 node 输出，把路径变量 `$Out` 覆盖了，
  下一轮 `Join-Path` 就拿 stdout 当路径，报
  `Cannot find drive. A drive with the name 'node.exe ' does not exist.`
- 负向测试里改名/删功能时必须**全局替换**，不能只改声明：
  第一版只把 `adoptSpawnAsHome()` 的声明改了名，调用点还叫原名，
  检查器照样匹配到 —— 表现为"这个负例没被抓到"，
  而**负例写得太弱和检查器漏检长得一模一样**。
