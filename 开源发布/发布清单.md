# 开源发布清单

> 这个文件夹是**上传 GitHub 用的成套材料**。仓库根目录的同名文件是权威副本，
> 发布时以根为准；这里放的是"给公开仓库用的版本 + 一份照做就行的清单"。

---

## 0. 一句话结论

**协议不用换 —— 继续 MIT。** 仓库里三处已经声明好了：

| 位置 | 值 |
|---|---|
| `LICENSE` | MIT，`Copyright (c) 2026 白钴 (White Cobalt)`，另有一段把"代码 MIT / 素材 CC0-CC-BY"分开写 |
| `gradle.properties` | `mod_license=MIT` |
| `neoforge.mods.toml` | `license = "${mod_license}"` |

理由：模组能不能进整合包是第一生死线，MIT 对整合包作者零负担；而"防止别人抄走卖钱"不是你的目标（真防也防不住，GPL 一样能拿去卖）。

**不要换的**：GPL-3.0（挡整合包）、Apache-2.0（对模组是过度设计）、CC0（会丢掉署名权，而且和 CC-BY 素材贴不到一起）。

## 1. 🔴 上传前必须解决的 4 件事

按"不解决就会出事"的顺序排。

### ① 「老柯」还没改名（商标风险，`docs/12` §1 早就定了）

`docs/12-发布与合规策略.md` 写着 NPC「老柯」必须换成原创名，占位名是 **「老渔夫 · 老陈」**，
但代码里还是老柯：

| 位置 | 数量 | 玩家可见？ |
|---|---|---|
| `src/main/resources/assets/anglertackle/lang/zh_cn.json` | 22 行 | ✅ 直接显示 |
| `src/main/java/**`（非注释） | 19 处 | ✅ 部分进聊天/界面 |
| `src/main/java/**`（注释） | 74 处 | ❌ 不可见，可慢慢改 |
| `tools/*.js`（检查器） | 5 个文件 | ❌ 但改名后会红，要同步 |

做法：先把 22 + 19 处玩家可见的改掉（含 `en_us.json`），再跑一次全闸；`tools/` 里那 5 个检查器
把期望值一起改掉。**这件事别拖到上架后**——DMCA 下架是整包下架。

### ② `CREDITS.txt` 的第三方素材表还是空的

文件里自己写着"发布前每一个第三方素材都必须在此登记，否则满足不了 CC-BY 署名要求、
也过不了 CurseForge / Modrinth 审核"。现在是：

```
| (none yet — first row goes here once M7 asset pass starts) |
```

**要么**把所有第三方素材逐行登记（文件名 / 原作者 / 来源 URL / 许可证 / 你改了什么），
**要么**确认现在真的没有第三方素材（全是自绘或程序化生成）——那就把这句话改成明确的声明。

### ③ 没有标准 Gradle wrapper，别人 clone 下来不能 `./gradlew build`

本机到 `services.gradle.org` / GitHub 不通，所以用的是 `tools/gradlew.cmd` + `tools/get-toolchain.ps1`
（从国内镜像拉 JDK + Gradle 到 `.jdk/`）。两个选择：

- **A（推荐，省事）**：README 就按现在这份写，明确"用 `tools\gradlew.cmd build`，或自备 Gradle 9.x"；
- **B（更标准）**：在能联网的机器上生成一次 `gradle wrapper --gradle-version 9.8`，
  把 `gradlew` / `gradlew.bat` / `gradle/wrapper/*` 提交进去。

### ④ `docs/01-设计总纲.md` §4 有「与《三角洲行动》的对应关系」整节

`docs/12` §1 的核心禁令就是**不要在公开内容里点名那个游戏**。如果 `docs/` 一起开源，
这一节（含表格）会原样公开。

做法：开源前把 §4 删掉或改成"参考了现代战术射击游戏的装备分层思路"这种不点名的写法。
`docs/` 里其它册子都安全。

## 2. 上传哪些、排除哪些

### ✅ 要上传

```
README.md          ← 本文件夹里这份（放到仓库根）
LICENSE            ← 仓库根那份，原样
CREDITS.txt        ← 仓库根那份，原样
.gitignore         ← 本文件夹里这份（替换仓库根那份，根那份只忽略 9 行，不够）
build.gradle
settings.gradle
gradle.properties
src/
tools/             ← 构建包装器、生成器、自检、调参器（值得公开，也是"可复现"的证据）
docs/               ← 建议公开（先处理上面 ④）
```

### ❌ 不要上传（`.gitignore` 已经挡住）

| 类别 | 具体 | 为什么 |
|---|---|---|
| 构建产物 | `build/`、`.gradle-home/`、`.gradle/`、`run/`、`versions/` | 体积、可重建 |
| 工具链 | `.jdk/` | 几百 MB，且是 GPL 发行物 |
| **个人调参** | `anglertackle-common.toml`、`默认配置_*.toml`、`*.toml.bak` | **你的调参不该进库**（默认值应该在 `Config.java` 里） |
| 备份 / 对照 | `_backup_anglertackle/`、`_baseline_1.21.1/`、`_fishsrc/`、`_scratch-nfrt/` | 只对开发机有意义 |
| 发布包 | `发布包/`、`发布包-1.6.5/`、`发布包_1.0.1/`、`导入用/` | 二进制重复 |
| 参考资料 | `参考资料/`、`fish_research/` | **可能含第三方版权图片**（真实鱼照） |
| 临时 | `Temp/`、`javac.*.args`、`45`、`Task`、`Configure` | 垃圾 |

> ⚠ `参考资料/新鱼拟饵原图/*.png` 那批"参考图"是**外部来源的真实鱼照片**吗？
> 如果是，**绝对不能**入库——那是最容易被投诉的一项。生成器只用它们做颜色参考、不打包进 jar，
> 但**放在公开仓库里就是二次分发**。

## 3. GitHub 上要点的几个设置

| 位置 | 怎么设 |
|---|---|
| 仓库根 | 必须有 `LICENSE`（文件名要 GitHub 认得，`LICENSE` / `LICENSE.md` / `LICENSE.txt`） |
| 仓库首页右侧 | 应自动显示 **MIT license**；没显示就是文件名/位置不对 |
| About → Description | 中英各一句，**不要**出现别的游戏名 |
| About → Topics | `minecraft` `neoforge` `minecraft-mod` `fishing` `1.21.1` |
| Releases | 每个版本挂 `anglertackle-x.y.z.jar`（这是"权威二进制"） |
| Issues | 开；模板里要求附 `logs/latest.log` |

## 4. CurseForge / Modrinth 上架字段

| 字段 | 填什么 |
|---|---|
| Game version | 1.21.1 |
| Mod loader | NeoForge |
| License | **MIT**（两个平台都要选；若平台强制整包单一协议，在描述里补一句"素材不受 MIT 覆盖，见 CREDITS"） |
| Source | 你的 GitHub 仓库地址 |
| Issue tracker | `仓库/issues` |
| 环境 | Client **and** Server（双端） |
| 分类 | Adventure and RPG / Equipment / Mobs（按平台实际分类选） |
| 图标 | 400×400 PNG（用现有 `icon.png` 放大或重画） |
